# 踩過的坑（2026-08-11 首次產出時實際發生）

每一條都是實際犯過、被驗收抓到才修的。照做可以省掉整輪重做。

> ⚠ 例子裡的公司一律寫成甲／乙／丙，技術名詞寫成〈…〉。
> **數字與名稱都是為了讓例子讀得通，不是可以沿用的內容。**

## 素材解析

**1. 以為報表沒有附圖**
圖表是 URL-encoded 的 data URI 內嵌在 `<img src="data:image/svg+xml,...">`。
第一次用 `src="([^"]{0,200})"` 去撈，因為長度上限完全沒有比對到，差點回報「HTML 裡沒有圖表」。
→ 撈 `src` 不要設長度上限；先判斷 `startswith("data:image/svg+xml")` 再 `unquote`。

**2. 同一張圖有兩份**
報表同時輸出 `xxx.web.svg` 與 `xxx.svg`。用檔名去重會漏，**用 SVG 內容雜湊**。

**3. 判讀文字比表格更值錢**
`<div class="explanation">` 裡是報表作者已經寫好的分析（含逐案查證的結論），
簡報敘事應以它為底再濃縮，而不是自己看表格重新編故事。
`.section-note` 則常藏口徑與資料品質警語（「不完整家族 3 個」「狀態未知 9 件」），要放進限制頁。

## 環境

**4. Bash tool 直接失敗**
本機 Bash tool 會回 `Top-level not found: C:\Program Files\Git\bin`。
→ 一律用 PowerShell，不要重試 Bash。

**5. python-pptx 不支援 SVG**
圖表必須先光柵化。用 `D:\vscode\playwright` 既有的 Chromium，
`PLAYWRIGHT_BROWSERS_PATH` 要指到該目錄，否則 playwright 會去 C 槽找瀏覽器並報錯。
截圖用 `device_scale_factor=3`，投影片放大後才不糊。

**6. PowerShell 管線**
`| Select-Object -First N` 會提早關掉管線，導致外層指令回傳 exit 255。
看到 255 但輸出正常，先確認是不是這個原因，不要當成腳本壞掉。

## 版面

**7. 字級鎖死就不能靠 autofit**
標題 24／內文 16 是硬規格，PowerPoint 的自動縮小字級不能用。
第一版直接照感覺排，轉圖後發現 7 個區域爆版（建議卡的「行動」被切掉、判讀帶壓到頁尾）。
→ 先寫 `text_h()` 量測（CJK 1.0 em、半形 0.55 em、×1.06 安全邊界），
每個區塊印出「可用 vs 需求」，`溢出 0` 才往下走。

**8. 卡片高度撐滿版面 = 下方一大塊空白**
把卡片高度設成「剩餘空間平分」，內容只有兩行時會很醜。
→ 卡片高度由內容決定，再把整組垂直置中。

**9. 兩張圖擠一頁，圖內字直接不能看**
一頁兩圖會讓每張圖寬度腰斬，圖內字掉到 7pt 以下。
→ 一頁一圖。頁數變多是可接受的代價，但要在回報中說明頁數為何超出原訂範圍。

## 圖表字級

**10. 全域放大字級會撞版，而且只撞少數幾張**
把 15.1 統一放大到 19：Key Players 沒事，但 IPC 長條圖的類別標籤蓋到長條、
機會四象限的 chip 文字衝出色塊。抽看兩張會誤判成「可以放大」。
→ 用重疊偵測器逐圖二分：先記錄原字級下**本來就存在**的重疊，
再由大到小試候選字級，出現**新**重疊就退一級。

**11. 重疊偵測太嚴會把好圖判成壞圖**
`getBBox()` 含行距留白，兩行堆疊的標籤會「重疊 1–2px」但視覺上完全正常。
一開始容忍值設 1px，Key Players 被判成不能放大（實際上 19 都沒問題）。
→ 容忍值設 3px。設完要再抽看一張確認判斷合理。

**12. 投影片上的圖內字級只跟 SVG 高度有關**
`on_slide_pt ≈ svg_font × (可用高度 × 72) ÷ svg_height`，**與 svg 寬度無關**。
想讓圖上的字變大，唯一有效的手段是**壓低 SVG 高度**（或給更大的版面高度）；
把圖畫寬完全沒用。這條決定了「使用者要求 14pt 做不做得到」的答案。

**13. 做不到就要說**
1180px 寬、字級 15.1 的圖，要在投影片上呈現 14pt 需要把圖放到 15 吋寬——超出版面。
→ 直接說明幾何限制並給選項（維持原字級／重排圖表／折衷），
不要默默交一個達不到需求的版本。

## 數字

**14. 跨列相加會重複計算**
把「甲 11 件已授權」＋「乙 10 件已授權」寫成「合計 21 件」，
但兩者有 12 件是共同申請——同一批專利被算了兩次。
→ **簡報上只出現 HTML 裡直接寫出來的數字**。真要合併，先確認兩列是否互斥；
不確定就分列陳述（「各 11 件與 10 件，其中 12 件共同申請」）。

**15. 件數 ≠ 技術量**
同一發明的跨國延伸會讓件數虛高（4 件其實是 1 個同族）。
判讀要同時看件數、同族數、法律狀態，並在簡報上點出這個陷阱——這正是情報顧問的價值。

## 驗收

**16. 用內容雜湊判斷圖表重複**
python-pptx 的 `image.filename` 在 pptx 內會被統一改成 `image.png`，
用檔名去重會得到「13 張全部重複」的假警報。→ 用 `image.sha1`。

**17. 程式化檢查過了不等於沒問題**
量測是估算，真正的換行由 PowerPoint 決定。
→ 一定要用 `pptx_to_png.py`（PowerPoint COM）轉圖，**逐頁**目視。不得抽樣。

**18. 迭代不要覆蓋前一版**
使用者會回頭比較 v1／v2／v3。每次改版存新檔。

## 自我檢查時才抓到的（v4 → v5）

程式化閘門全綠、也逐頁看過之後，仍然有三個問題留到再看一輪才發現。
**「閘門過了」不等於「沒問題」，交付前要再用讀者的眼睛掃一次。**

**21. 封面的頁碼寫死 → 直接錯一頁**
封面寫「第 3–14 頁一頁一圖；第 15 頁收斂為行動」，但實際圖表頁是 3–15、路線圖在 16。
頁數在迭代中變過，手寫的頁碼沒跟著改，而且**沒有任何檢查會抓到**——
它不是版面問題也不是數字問題，是「內容自我指涉」的問題。
→ 封面頁碼一律用佔位符 `{chart_first}` / `{chart_last}` / `{last}` / `{n_charts}`，
由 `deck_layout.page_vars()` 從實際頁數推導；`check_content.py` 會擋掉寫死的頁碼。
⚠ 同一類風險還有：「本報告共 N 頁」「詳見第 N 頁」——凡是簡報講自己的結構，都要導出不要手寫。

**22. 重疊偵測的容忍值不能一視同仁**
為了避免把「兩行文字的行距留白」誤判成撞字，容忍值設成 3px，
結果 `cpc_L4` 在字級 18 時類別標籤緊貼長條也被放行——**文字碰到色塊是看得出來的瑕疵**。
→ 分開設：`text↔text` 用 3px（行距留白），`text↔rect` 用 1px（碰到就是碰到）。
⚠ 副作用要知道：收緊容忍值會讓「原字級下本來就微疊」的元素進入基準線，
反而放寬該元素的成長空間（`applicant_ranking` 因此從 16 升到 18）。
所以改容忍值之後**必須重看受影響的圖**，不能只看數字有沒有變。

**23. 扁平圖表置中 → 版面像沒收好**
subclass 總覽這類很扁的圖（ratio 6–8）在高的圖表區裡置中，上下各留一大塊空白，
看起來像忘了排版。→ 圖高不到區塊 6 成時改**靠下對齊**，讓圖與下方判讀帶成為一組，
留白集中到標題下方，讀起來像刻意的呼吸空間。

## 使用者回饋抓到的敘事問題（v5 → v6）

版面與數據都對，簡報還是可能「講得不好」。這五條全部是**敘事層**的問題，
任何程式化閘門都抓不到，只能靠寫的人自己回頭讀一次。

**24. 標題的量詞與內容對不上**
第 2 頁結論句寫「可切入的是**兩個**低密度區」，下面卻列 A/B/C/D **四個**方向。
→ 標題裡的量詞必須與項目數、分類完全一致。改成
「四類研發方向：2 個機會區、1 個差異化區、1 個迴避區」。

**25. 共同申請的件數被讀成加總**
寫「甲（11 件授權）與乙（10 件授權）」，讀者自然讀成 21 件不同權利，
實際兩者 12 件是共同申請。→ 先講陣營、明說不可加總、再給**算得出來的**聯集（15 件）。
⚠ 能不能算聯集要看報表有沒有 ID 明細：`patent_ids` 有 → 件數可算；
`granted_count`／家族數／技術群數沒有明細 → **只能分列**，不可硬湊。
（這比第 14 條更進一步：14 說「不要加」，25 說「什麼情況可以算、怎麼算」。）

**26. 一個沒有訊號的主題佔了四頁**
IPC 4/5 階、CPC 4/5 階各一頁＝4 頁，但實際結論只有「分類就只有一種」。
→ 頁數要配**訊號量**不是圖表數：分類種類少就收成一頁「分類碼告訴我們什麼」，
其餘轉成判讀文字。⚠ 這條優先於「所有圖都要用」，但未使用的圖必須在回報中列出與說明。

**27. 競爭者頁只給定位、沒給機構**
Key Players 頁講「幾國、幾主題、幾件已授權」是定位資訊，RD 拿不去用。
→ 另開一頁「主要玩家在做什麼：各家的技術構型」，寫各家實際主張的機構。
這些在報表判讀原文裡通常都有，不必外求。**這是對 RD 價值最高的一頁。**

**27b. 有了玩家頁，但寫成敘述句照樣掃不了**
第一次改完「主要玩家在做什麼」，內容對了，但每家寫成一整段散文，RD 還是得逐字讀。
→ 改成**關鍵詞**：有時序推進的用「年份 構型 → 年份 構型」演進鏈，
單一平台深耕的用「關鍵詞・關鍵詞・關鍵詞」；並用 `主體｜內容` 格式讓主體加粗上色。
⚠ 顆粒度受限於來源：更細的請求項用語要回讀 claim，HTML 沒有就不准推測，
在頁尾標明這個邊界。

**28. 時間線頁沒有上層結論**
只寫「哪一年有幾件」等於把圖再唸一次。
→ 先給一句可記住的演進結論（機械傳動 → 阻力控制 → 電機化），圖退為證據；
階段名稱用技術語言，不要用「早期／中期／近期」。

## 標籤欄版面與量詞（v8 → v10）

**29. 純文字頁的行長預設就超標**
滿版單欄每行約 **50 個全形字**，中文舒適區間是 25–35。字級鎖死 16pt 不能縮字，
只能切寬度。→ 用 `layout: "label"` 把左欄 2.2in 分給主體名，行長降到約 40。
⚠ **不要改成硬分兩欄**：兩欄各只剩約 23 單位，並列專利號單串（「CN 121754861、
CN 121754862、CN 223248694」）就超過一行，會被迫斷行，比原本更難讀。

**30. 分隔線壓在文字上——而且裕度表報「溢出 0」**
`textbox()` 每段預設帶 6pt `space_after`，但 `text_h()` 以 gap=0 估高，
差額讓列間細線落在上一列最後一行的字上。裕度表用的是同一套估算，**當然抓不到**。
→ 列高一律加 `ROW_PAD`，並把該版面的 `space_after` 設為 0。
⚠ 通則：**估算器自己的誤差，估算器不會告訴你**。凡是「量測通過但實物有問題」，
先懷疑量測與繪製用的不是同一組參數。

**31. 細線太細會隨機消失**
分隔線設 0.008in，在 96dpi 下只有 0.77px，次像素導致**部分細線整條不見、部分還在**。
目視時很容易誤判成「這兩列本來就沒分隔」。→ 至少 0.014in。

**32. 裸數字掃描器忘了吃空白 → 110 處假警報**
第一版比對「數字的下一個字元是不是量詞」，但簡報寫的是「4 件」（中間有空白），
於是把全部合格的句子都報成裸數字。→ 比對量詞前必須容許空白。
⚠ 更通則的：**掃描器噴出大量結果時，先懷疑掃描器**。真正的問題很少一次出現 110 處。

**33. 補量詞會撞欄位上限**
封面 `stats_note` 補完量詞從 32.7 漲到 37.3 單位，超出上限 34.4。
→ 換句子結構（「技術主題 5 個 ＋ 功效主題 8 個」→「技術 5 個、功效 8 個主題」），
**不要為了塞得下又把量詞拿掉**——被否決的另一個候選更短，但 5 又變回裸數字，等於白改。

**34. 左欄標籤沒有上限就會爆**
左欄只有 2.2in ≈ 9.3 單位（約 8 個全形字）。公司全名放進去會換行，
把右欄的對齊整個擠掉。→ `check_content.py` 事前擋；縮短標籤，**不要加寬左欄**——
加寬就把行長改善吃回去了。

**38. 行高估算全域低估 15%——`LS` 不是行高**
`LS = 1.22` 是設給 PowerPoint 的 `line_spacing`，意思是「單行行距的 1.22 倍」，
而中文字型的單行行距本身就大於字級。用 PowerPoint COM 的 `TextRange.BoundHeight`
實測：16pt Microsoft JhengHei ＋ LS 1.22 的實際行高是 **22.4pt＝字級的 1.40 倍**，
不是 19.5pt。6 段就少算 0.24in，足以把最後一行切出框外。
→ 量高度用 `LS_RENDER = 1.40`（實測值），不要用 `LS`。
⚠ 修正後圖表最多只掉 0.4pt（判讀帶有 `max()` 下限吸收），**代價幾乎是零**，
但在此之前所有區塊都比帳面上更擠。

**39b. 寫死的倍數不會跟著幾何走**
`budget()["text_page"]` 原本寫 `_per_line(...) * 14`。行高從 19.5pt 改成實測的 22.4pt 之後，
內文區實際只放得下 **12** 行，但上限還停在 14——**閘門從「保守」變成「高估」而沒人知道**。
→ 由幾何算出來（`_text_page_lines()`），不要寫死。凡是「乘一個看起來合理的數字」
都要問「這個數字是從哪來的，幾何改了它會不會跟著改」。

**39. 自己跟自己比的裕度檢查，永遠不會失敗**
路線圖頁原本查 `note("限制框", lim_h - 0.34, lim_need)`，而 `lim_h = lim_need + 0.34`
——avail **恆等於** need，這個檢查在數學上不可能報錯。限制頁加到 5 則、最後一則
被頁尾切掉時，裕度表仍然報「溢出 0 個」。
→ 區塊高度若是「內容需求 ＋ 固定 padding」算出來的，就**不要查它自己**，
要查它跟兄弟區塊加起來有沒有超過整頁可用高。
⚠ 通則：寫裕度檢查時先問「**這個 avail 有沒有可能小於 need**」。答案是「不可能」
就代表這行是裝飾品，把它換成真正會失敗的那個比較。
⚠ **同一個坑出現了三次**：路線圖頁、建議頁、判讀帶全都是「區塊高＝內容需求＋固定
padding」再拿它跟自己比。修了第一處要**回頭把同型的全找出來**——用語意搜尋
（`note(` 的每個呼叫點逐一檢視），不要只修被踩到的那一個。

**41. 中文標點掉到行首——逐頁目視十幾輪都沒看出來**
python-pptx 產的段落沒有 `eaLnBrk` / `hangingPunct`，run 也沒有 `lang`，PowerPoint
就不套東亞換行規則，句號、逗號、右括號會單獨掉到下一行行首（實測：第二行開頭是
「）：風磁複合」、第三行開頭是「：馬達自鎖」）。
→ `textbox()` 對每個段落設 `eaLnBrk="1"`、`hangingPunct="1"`，每個 run 設
`lang="zh-TW"`。三者缺一不可——沒有 `lang`，前兩個屬性等於白設。
⚠ **這個瑕疵 v1–v16 每一版都有，而且是 sub agent 用全新的眼睛才抓到的。**
它不是溢出、不是重疊、不是裁切，所有閘門都不會叫，而且**讀的人會自動把標點讀回
上一行**——自己看自己的產出十幾輪都會漏掉。
⚠ 也因此：**全頁縮圖不足以判斷這類瑕疵，要放大到 2× 以上看行首**。我第一次看
全頁圖時還誤判了另一頁（那頁其實正常），放大才分清楚。

## 資料庫補查（v8）

**35. 該查的只有一種頁面**
報表判讀是二手轉述（「〈構型 A〉的機構」），對統計、趨勢、定位頁都夠用；
**只有競爭者構型頁不夠**——同一句概括底下可能是兩件構型完全不同的專利。
→ 條件與規則見 SKILL.md「何時該去資料庫補查」。⚠ 只補敘述、不補統計：
DB 現況與報表快照可能不同調，混用會讓同一份簡報出現兩個口徑。

**36. 別自己接 psycopg**
既有的 `query_database` 帶語法白名單與 `SET TRANSACTION READ ONLY`（且 pooler
會忽略連線字串上的唯讀選項，所以唯讀是綁在**交易**上的）。自己接等於繞過保護。
MCP 沒掛上時就 in-process 呼叫同一支函式。
⚠ `.env` 不會自動載入，`DATABASE_URL` 取不到會退去拼 `PG*`，密碼含 `@` 就炸在
`failed to resolve host`——呼叫前先自行把 `.env` 讀進 `os.environ`。

**40. 只讀了代表性案件，卻寫出涵蓋全部案件的通則**
補查取回 15 件，只挑了 7 件印出來讀，然後寫下「三代之間**機架與拉繩出力路徑一路沿用**」。
使用者一問「這是讀完全部還是只讀代表性的」就破功——回頭補讀才發現**2020 那一代的
請求項根本沒有機架也沒有拉繩**（標的是阻力裝置元件），無從「沿用」。那句話是推論，
不是讀出來的，違反本 skill 排第一位的規則。
→ **斷言的範圍必須等於證據的範圍。** 讀了 7 件就只能講那 7 件；要講「三代都…」
就得把三代全部讀完。取回 ≠ 讀過，中間那一步沒有任何閘門會提醒你。
⚠ 補讀之後往往會得到**更好的發現**：這次補完看見的是「保護標的層級在換」
（2020 只保護元件、2022 轉整機、2024 兩者並行），對迴避評估比原本那句有用得多。
偷懶少讀的代價不只是錯，還包括錯過真正的洞見。

**37. 報表表格的 patent_ids 要從 report.json 讀，不要從終端輸出讀**
PowerShell 直接印 HTML 片段會有編碼破損，中文變亂碼、頓號變 `??`，
當時據此把某公司的 ID 讀成了另一家的。→ 一律從 `report.json` 以 UTF-8 讀。

## 寫程式時

**19. 不要在迴圈內改共用的候選清單**
`fit_render_charts.py` 早期版本在處理某張圖時把 `cands` 清空，
導致後面所有圖都不再嘗試放大。→ 用區域變數，不要動外層狀態。

**20. 一次性內容不准寫進 skill 或 scripts**
版面引擎只吃 content dict；解析腳本用**結構**（class、屬性、位置、順序）辨識元素，
不比對特定字串。換一批專利、換一個技術領域都要能直接跑。
