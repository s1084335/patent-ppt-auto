# 專利分析報告——專業度標準與內容方向

> 本檔是報告內容品質的**唯一標準**，由兩份定案範例反解而來：
> 「滑雪機專利技術地圖_整合分析_V2」（11 頁）與「自走式割草機_專利情報整合分析」（10 頁）。
> 產報告的 CLI 寫每一頁之前都要對照本檔；違反「硬標準」任一條＝不合格，重寫。

## 🔴 通用性（最優先的一條）

本 skill 服務**平台上所有 workspace**——任何技術領域（健身器材、割草機、
或未來任何主題）、任何資料規模都走同一份標準。因此：

- 兩份參考範例是**品質校準用的標杆**，示範「寫到多深才合格」；**不是**可以套用的
  內容模板。每個 workspace 的發現、分期、Key Player 都必須從**該 workspace
  自己的資料**產生。
- 🔴 **本檔的示例一律用佔位符**（`〈主題A〉`、`〈甲公司〉`、`〈具體機構＋作動方式〉`），
  不寫任何真實主題名或公司名。⚠ 2026-08-10 實測發現本檔自己違反過這條六處
  ——示例句直接寫了真實主題名、公司名與機構描述，而那批資料**正好就是
  當時在跑的 workspace**，CLI 讀到現成句子會直接抄，而抄來的句子看起來完全合格。
  ⚠ 免責聲明擋不住照抄：寫「這是標杆不是模板」沒有用，**把具體名詞拿掉**才有用。
- 頁面數量隨資料伸縮：主題多、玩家多的 workspace 可以多開 KP 頁與附錄頁；
  資料撐不起某頁（分期只有一期、KP 沒有明顯領導者）就**不硬寫**——
  寧可少一頁，不可有一頁空話。
- 不得假設欄位值的語言、格式、國家組成（例：不得假設主要國家是 CN、
  不得假設申請人是公司而非個人）。
- 任何寫死特定 workspace 名稱、特定技術詞彙、特定公司名的規則都是缺陷。

## 🔴 有圖頁與無圖頁是**兩種寫法**，不是同一種寫法配不同字數

⚠ 這是最常出事的一條。兩者的差別不在「寫多寫少」，而在**文字要回答的問題不同**：
圖已經回答了「多少、誰、什麼趨勢」，有圖頁的文字若再講一次，整頁等於只講了一件事；
無圖頁沒有圖分擔，文字必須自己撐起結構，寫成三句話就是一張白框。

| | **有圖頁** | **無圖頁** |
|---|---|---|
| 文字的任務 | 寫圖上**看不出來**的 | 整頁內容**全部**由你產生 |
| 該寫什麼 | 機構層手段、為何如此、意味什麼、要注意什麼 | 該頁要回答的問題，逐區寫完 |
| **不得寫** | 🔴 圖上讀得到的（排名、件數、誰最多、哪年高峰） | 沒有具名對象或數字的空話 |
| 條數 | **3 條**（側欄）／最多 4 條 | 3–5 條，可分區、可加小標 |
| 每條長度 | **約 40 字**（側欄窄，超過就疊字） | 單欄約 90 字／兩欄約 40 字 |
| 撐不滿時 | 正常——圖是主角 | **不要開這一頁** |

### 有圖頁：文字與圖**分工**，不重複

- ❌「前三大申請人合計 32 件，占 58%」← 圖上一眼就看得到，寫了等於沒寫
- ✅「前段集中在單一機構路線；第三名走的是另一條技術路徑，與前兩家不衝突」
  ← 圖上看不出「路線是否相同」，這才是文字的價值
- 圖已點名的對象，文字可以**接著講它做了什麼**，但不要重報一次它的數字。

### 無圖頁：整頁都是你的字，要自帶結構

- 每條都要有**具名對象與數字**（誰、哪個主題、幾件、佔比多少）。
- 分區寫（例如「需迴避／可切入」「方向｜依據｜行動」），不要平鋪五條 bullet。
- 撐不起一頁就**不要開這一頁**（見上方通用性：寧可少一頁，不可有一頁空話）。
  開了卻寫不滿，比不開更糟。

⚠ 組版端會掃描每一頁的正文區；內容過少標 `empty_body`、超出容量標
`text_overflow_estimated` 或直接 `points_dropped`（**條目被丟掉，不是縮小字**）。
這些都是**事後告警不是修補**——它只會告訴你哪頁出事，不會替你補內容或重寫。

## 一、專業度七條硬標準（兩份範例共同的 DNA）

### 1. 標題必須是判讀，不是欄位名

每頁標題＝「主題：這頁的結論」。讀者只看標題列就能得到完整論述。

| ❌ 裸名詞 | ✅ 範例的寫法 |
|---|---|
| 申請趨勢 | 申請趨勢：2021–2023 為布局高峰 |
| 技術分布 | 技術分布：件數是第一層，競爭者廣度才見結構 |
| 技術分類全景 | 技術分類全景：件數 ≠ 技術多樣性 |

### 2. 每個統計數字都要被「校正」——裸數字＝不專業

範例從不讓數字自己說話，每個數字旁邊都站著一個「但是」：

| 裸數字的誤導 | 範例的校正 |
|---|---|
| 19 件傳動專利 | 同族合併後僅 8 個技術群——**件數 ≠ 技術多樣性** |
| 2020、2025 有成長 | 多為同一技術的跨國同族延伸——**表面成長 ≠ 新技術湧現** |
| 照明只有 4 件，是藍海？ | 4 件全來自 1 家——**低件數 ≠ 藍海**（倖存者偏差） |
| 2024 後件數回落 | 公開延遲約 18 個月——**回落 ≠ 降溫** |
| 速度控制 45 件最多 | 45 件只有 9 家，集中單一集團——**件數 ≠ 競爭者廣度** |

寫任何一個數字前先問：**這個數字最容易被誤讀成什麼？**把校正寫在數字旁邊。

### 3. 發現要具名——三個「必須先講的發現」

發現不是流水帳，是**點名**。每個發現＝「標籤（數字或名字）＋一句話結論」：

- 「**19→8** 件→群」——件數不等於技術多樣性
- 「**2022 & 2024** 真爆發年」——其餘年份多為同族延伸
- 「**〈某家〉／〈某家〉** 唯一全領域」——橫跨三大領域且跨四地布局

⚠ 上列是**格式示例**（取自另一批資料），不是內容模板。標籤由你這批資料產生，
不用固定句型。找不到三個有份量的發現＝分析還沒做完。

🔴 **落點**（2026-08-10 定案）：這三個發現寫進**研發切入建議頁的「依據」欄**，
不另開執行摘要頁——發現本來就是建議的依據，分兩頁講就是同一件事講兩次。

### 4. 結論先行——建議放前面，不是壓軸

割草機範例第 2 頁就是「研發方向建議」，每條建議三欄：
**研發方向與具體題目｜專利地圖依據｜建議專利行動**。
依據必須引用自己報告裡的數字（「能源管理僅 2 件／2 家＝專利數量最少」），
行動必須具體到申請策略（「以發明為主搶先卡位；主張材料＋結構＋控制邏輯之組合」）。

### 5. 方法論誠實——每頁都聲明自己的限制

範例的可信度來自它主動講自己看不到什麼：

- 頁尾常駐：「本分析非侵權迴避（FTO）結論」「競爭者結構強度為純專利訊號，非產品核心度」
- 專頁交代（判讀說明頁）：可觀測性偏差——看不到營業秘密、未申請、開發失敗的技術；
  跨國同族放大可見度；單一新興案數量少 ≠ 不重要
- 不確定就說：「需逐案確認」「需人工覆核」「需使用者痛點調查量化確認後定案」

#### 5-1. 判讀說明與結語頁（`reading_guide` 版型）怎麼寫

從滑雪機 V2 p11 反解，這頁有**四個必填區**，缺一頁就散：

| 區 | 範例原文 | 你要寫什麼 |
|---|---|---|
| 副標（一句話） | 「件數反映的是『可觀測的法律布局密度』，不等於技術成功或市場價值，避免把低專利密度直接當成藍海。」 | **這份報告最該防的那一種誤讀**。一句，且要指名道姓講出誤讀的內容 |
| 左區標題 | 可觀測性偏差（讀圖須知） | 固定 |
| 左區四條 | 見下表 | 四個角度各一條，依本 workspace 實況填 |
| 右區三條結語 | ①核心已位移 ②先避牆、再切空白區 ③提早公開為先手 | 編號＋4–8 字短標＋一句解釋 |

**左區四條的四個角度**（角度固定，內容依資料換；不得少寫、不得換成別的話題）：

| # | 角度 | 範例寫法 | 你要回答的問題 |
|---|---|---|---|
| 1 | **資料涵蓋邊界** | 「清單已含失效/放棄/屆滿案，但仍看不到營業秘密、未申請與開發失敗的技術。」 | 這份清單**含**什麼、**仍看不到**什麼 |
| 2 | **同族放大效應** | 「跨國同族會放大布局者的可見度：原始件數量『部署強度』，技術群量『路徑多樣性』。」 | 兩個數字各量的是什麼，別把部署強度當技術多樣性 |
| 3 | **小樣本不等於不重要** | 「單一新興案（如 OxeFit）數量少≠不重要，可能只是尚未形成跟進。」 | **具名**點出本次資料裡那個「少但值得看」的對象 |
| 4 | **低密度要外部校正** | 「低密度領域須配 VOC／銷量／競品採用資料，才能區分真空白區與偽空白區。」 | 想從低密度推出機會，還缺哪些**專利以外**的資料 |

🔴 第 3 條**必須具名**——寫「有些新興案值得注意」等於沒寫。整頁沒點到任何具名
對象時組版端會告警（鎖七·具名）。

**右區三條結語的形狀**：都是**判斷或行動**，不是數字總結。
❌「共 55 件，中國最多」（那是前面頁講過的事實）
✅「先避牆、再切空白區：繞開〈甲公司〉與〈乙公司〉的〈高密度主題〉；主攻〈低密度主題群〉。」

**數字口徑要說明時**：計數單位、同族合併、共同申請、分類覆蓋這四段的正式說法
在 `report_data.json` 的 `table_display.reader_guide`（每則含 `title`／`body`），
**要用就逐字照抄**，不要自己改寫。⚠ 但它們是**口徑定義**，不是可觀測性偏差
——不得拿它們去頂替上表那四條，那四條講的是「不能怎麼推論」，是兩件事。
本頁版面只放得下四條偏差；口徑定義通常放頁尾註記或附錄。

**這頁可以不出**——割草機範例就沒有獨立這頁，改把偏差說明下沉到各頁副標
（「2024 後回落主因公開延遲(約 18 個月)」「Y 軸為純專利訊號，不等於產品核心度」
「倖存者偏差校正後」）。⚠ 可省的是**頁**，不是**四個角度**：不出這頁就要逐頁
把對應角度寫進副標或頁尾，不能整份報告都不提。

### 6. Key Player 要「深入」，不是排名表

#### 🔴 B-6 分頁規格：**3 頁，依有無技術軌跡分組**（定案，不是建議）

**軌跡判準＝該申請人的專利落在 ≥3 個不同申請年。**
⚠ 不是「最晚年 − 最早年 ≥3」——兩件相隔四年但只有兩個年份，那是兩個點不是軌跡。

| 頁 | 收哪些人 | 寫什麼 |
|---|---|---|
| **KP①** 領導陣營 | 件數最前、**有軌跡**者（常是彼此有共同申請的一組） | 逐年技術演進主線＋三數字卡＋FTO 威脅框。🔴 有共同申請關係時**必須拆開「共同 N 件」與「各自獨立 N 件」**——合計數字會把兩家講成一家，也看不出誰主導 |
| **KP②** 對照組 | 件數相當但**路線不同**的兩家 | 左右兩欄比較：技術路線、布局地區、進場時間各差在哪 |
| **KP③** 利基新興 | 其餘各家（含**無軌跡**者） | 小卡矩陣，**每家至少一句**——不是只提前兩家 |

- ⚠ 三頁都**不放專利號**：一個號佔掉一行卻不給讀者判斷。同樣版面，拿掉號可以多寫
  一個機構——那才是濃縮（見第四節「濃縮的判準」）。
- ⚠ 人數不足以撐三頁時可少開，但**不得把三組混成一頁**：混在一起就看不出
  「誰在推進、誰在對峙、誰在試水」這三種角色。

#### 三種頁型的共同要求

範例給 Key Player 三種頁型（見第二節），共同要求：

- **技術演進邏輯**：逐年時間軸＋一句演進主線（「阻力效果 → 傳動可靠性 → 電機化 → 失效安全」）
  ——這要**讀過該申請人的專利內容**才寫得出來，不是從件數推的
- **三數字卡**：家族件數／技術群數／布局地區數
- **FTO 威脅框**：威脅是什麼形狀（單一案還是整體平台）、哪些地區已覆蓋、
  新品沾到什麼要逐項比對獨立項
- **技術描述到機構層**：寫到「〈零件A〉＋〈零件B〉如何配合作動」的粒度
  （工程師看了能畫草圖）——不是「傳動技術」這種空話

**🔴 怎麼拿到這種深度：自己去查，不要等資料餵過來**

`applicant_strength_profile` 的每一列都帶 **`patent_ids`＝該申請人的全部專利 id**
（2026-08-10 使用者定案「每家全取」）。拿到之後：

```sql
SELECT id, "公開公告號", "發明名稱", "文獻備註"
FROM core_layer.patents WHERE id IN (...)
```

⚠ **`文獻備註` 是平台 AI 為每件寫的 2–3 句技術摘要，掃讀整批的首選**
（見 `data_access.md`）。一次撈十幾件也不會撐爆 context，讀完就知道這家在做什麼。

⚠ **不得只寫專利號與標題**——標題常是「一種健身器材」這種無資訊量的字串。
要寫出**技術內容**：

| ❌ | ✅ |
|---|---|
| 2024 電機化 | 2024〈子主題〉：〈具體機構＋作動方式〉，5 件同架構 |
| US-xxx《一種〈產品〉》 | 〈零件A〉與〈零件B〉如何配合達成〈功能〉，省掉〈原本需要的部件〉 |

⚠ **資料層刻意不預先算摘要**：預先算好餵給你，你就無法追問、無法依這次的
最大目標調整深淺。取證權限是為了讓你自己判斷要看哪幾件、看多深。

### 7. 圖表自己會說話——編碼說明＋來源註

- 圖表旁一行小字交代視覺編碼：「條長＝件數｜顏色＝集團涉入｜右側數字＝申請人數量」
- 每頁底部：資料來源＋統計期間＋母體＋必要限制聲明
- 歸戶要交代：「Milwaukee＋TTi 併計 TTi 系；MTD 併入 SBD 集團」——合併過的計算必須說

## 一之二、🔴 主題類與趨勢頁的**欄位規格**（定案，不是建議）

⚠ 這三頁最容易被寫成空泛的文字頁。定案早已規定它們的形狀，照做即可。

### B-2 申請趨勢：要把技術**和時間套著看**

- 圖：年度申請件數（不變）
- 敘述：用年度四欄寫「真爆發 vs 同族延伸」
  ——`10 件 / 10 族 / 5 群 / 2 群首現` ＝真爆發；`4 件 / 2 族 / 1 群 / 0 首現` ＝同族延伸
- 🔴 **要點名主題標籤**：「2024：**〈主題A〉** 5 件、**〈主題B〉** 1 件」
  ——只寫「2024 再起 11 件」等於沒把技術與時間扣起來

### 🔴 主題頁：正文用**圖**，表格進附錄（2026-08-10 使用者定案）

「同樣的東西做一次就好」——同一份主題資料不得在正文既畫圖又列表。
兩個通道各有**專屬圖**，正文用圖，完整表格放附錄供回查。

| 通道 | 正文呈現 | 圖回答了什麼 | 文字補什麼 |
|---|---|---|---|
| **技術主題** | **主題演進圖**（早期 vs 近期雙條，依近期件數排序） | 哪些主題在長、哪些在退、各多少件 | **機構層手段**——這個主題實際是怎麼做的 |
| **功效主題** | **機會四象限板**（密度 × 廣度，chip 標「件/家」） | 哪一格擁擠、哪一格空、誰涉入 | **逐象限行動**——這一格該追、該守、還是該繞 |

⚠ 為什麼用圖不用表：主題數常超過十個，表格在簡報字級下**列不完也讀不動**；
時間趨勢與密度分布本來就是圖的語言。表格的價值在「回查具體是哪幾件」，
那是附錄的任務。

### B-3 技術主題：正文＝主題演進圖

- 敘述：具名發現卡，**點名主題講技術內容**（不是講佔比）
  - ✅「〈某主題〉：〈某家〉近三年 5 件同架構——**〈具體機構＋作動方式〉**」
    ← 機構層，讀過專利才寫得出來
  - ❌「〈某主題〉6 件，〈某家〉獨占 83%」← 圖上看得到，等於沒寫
- ⚠ 敘述**不放專利號**（版面留給技術內容）；要回查的人翻附錄。

### B-4 功效主題：正文＝機會四象限板

- 逐象限給**行動**，不是只標密度：高密度·高廣度＝必守核心／迴避設計；
  低密度·高廣度＝值得追；低密度·低廣度＝需做使用者痛點調查（專利資料無法區分）；
  高密度·低廣度＝單一玩家壟斷型。
- 🔴 **空象限要明說「本案無此類」**，不是留白——留白讀者不知道是沒有還是漏了。
- 每個 chip 標「件/家」兩個數字；顏色表示龍頭是否涉入。

### 附錄主題全表：保留**代表專利號**

```
主題｜件數｜參與公司｜主要玩家｜代表專利
功效主題｜件數｜主要技術手段｜代表專利
```

- `代表專利` ＝前三大申請人各取一件的專利號。⚠ **只在附錄出現**，正文敘述不放。
- `主要技術手段` ＝**讀該主題前五筆專利的 `文獻備註`**，統整「怎麼達成的」。
  ⚠ 這欄不是查得到的欄位，是**你讀完專利內容後寫出來的**。

## 一之三、🔴 必出頁與取證深度

### 必出頁（沒有就是不合格，不是「依內容決定」）

| 頁 | 為什麼必出 | 範例 |
|---|---|---|
| **研發切入建議** | 使用者的最大目標就是要這個。只診斷不建議＝沒回答問題 | 滑雪機 p3／割草機 p2 |
| **Key Player 深入** | 「誰是對手、他在做什麼」是報告的核心價值，一張象限圖不夠 | 滑雪機 p8–10（3 頁） |
| **判讀說明＋三條結語** | 收尾要給判斷，不是只講限制 | 滑雪機 p11 |

⚠ 其餘頁仍「依內容決定」；上表三頁是**不能省的骨架**。

### 🔴 技術內容必須下到機構層——這是取證權限存在的理由

你有 `report-research` MCP 的唯讀查證權限（可查任一報表、可下 SQL 查 DB）。
那個權限**就是為了讓你寫出聚合數字寫不出來的東西**：

⚠ 示例一律佔位符（見「通用性」）——你要填的是**這批資料查證後的實際內容**：

| ❌ 從聚合數字就寫得出來（不合格） | ✅ 讀過專利內容才寫得出來 |
|---|---|
| 〈主題A〉6 件，〈甲公司〉獨占 83% | 〈主題A〉：**〈具體機構＋作動方式〉**，〈甲公司〉5 件同架構 |
| 〈主題B〉10 件，top3 占 80% | 〈主題B〉：**〈零件如何配置達成該功能〉**，省掉〈原本需要的部件〉 |
| 〈甲〉14 件、〈乙〉13 件 | 兩者 12 件共同申請，實為同一陣營；近年集中在〈子主題〉 |

判準：把主題名遮掉後，右欄的描述**還能讓工程師畫出草圖**＝到機構層了；
只剩「電機化」「傳動技術」這種類名＝還沒到。

**怎麼拿到**：`applicant_strength_profile` 的每列帶 `patent_ids`（該家全部專利 id）；
`文獻備註` 是平台為每件寫的 2–3 句技術摘要，**掃讀整批的首選**。

```sql
SELECT id, "公開公告號", "發明名稱", "文獻備註"
FROM core_layer.patents WHERE id IN (...)
```

⚠ **多家申請人都要抓出來講**，不是只講第一名。範例的 KP 頁涵蓋領導者、對照組、
利基新興三種角色，各有各的技術路線。

## 二、內容方向：目標頁面架構

🔴 **這張表是備選版型庫，不是必出清單**（2026-08-07 使用者定案）：
「這些呈現形式不是說一定每次都要有這幾種出現，而是要根據內容而呈現的」。

- 每次出哪幾種頁、各出幾頁，由**該批資料的內容**決定；
  **沒有那個內容就不出那一頁**——不硬湊、不佔位、不填模板句。
- 例：軌跡（不同申請年 ≥3）一家都沒有 → 不出 KP 深入的時間軸頁；
  利基玩家不足 → 不出小卡矩陣；分類 <3 種 → 整頁不出；
  封面統計卡資料不足 → 少一格。
- ⚠ 判斷「出哪一頁」的是規劃端（CLI／SlidePlan）；資料元件只回資料
  （有幾家、有無軌跡、幾個主題幾個國），不預設呈現形式。
- ⚠ 同理**不得把數字硬做成表格**：四面向（件／族／國／技術廣度／法律狀態）
  在範例中的形狀是象限座標、數字卡與一句定位，不是一張屬性表。

綜合兩份範例，一份合格的報告依此敘事鏈組頁（實際頁數隨資料規模伸縮）：

| 段 | 頁 | 圖 | 內容 | 對齊範例 |
|---|---|---|---|---|
| 開場 | 封面 | — | 主標＋統計期間＋3–4 統計卡＋「分析框架」說明條（一句話講方法與偏差校正） | 兩份皆有 |
| **結論** | **研發切入建議** | 無圖 | 三欄「**方向｜依據｜行動**」。🔴 **具名發現寫進「依據」欄**——不另開執行摘要頁 | 割草機 p2＋滑雪機 p2/p3 |
| 證據·時間 | 申請趨勢 | 年度件數 | 高峰年份；真爆發 vs 同族延伸；**點名該年的主題標籤**；公開延遲警語 | 兩份皆有 |
| 證據·技術 | **技術主題** | **主題演進圖** | 早期 vs 近期雙條；文字寫**機構層手段** | B-3 |

| 證據·空間 | 國家布局 | 受理局分布 | 地域分布＋類型組成＋地理空白區判讀（「本清單無」≠「該國無」） | 滑雪機 p6 |

| 證據·競爭 | **申請人年度矩陣** | 年 × 申請人 | 各家**過去的軌跡**：何時進場、是否連續、哪年集中。⚠ 解讀可精簡，圖本身就是主角 | — |
| 證據·競爭 | 競爭定位象限 | KP 象限 | 跨國布局深度 × 技術廣度，泡泡＝家族件數；定位分類（全領域／單一深布局／利基探索／前案） | 滑雪機 p7 |
| 證據·競爭 | KP 深入 ×3 頁 | 無圖 | ① 領導陣營（拆共同 vs 各自獨立）② 對照組兩欄比較 ③ 利基新興小卡。🔴 **不放專利號** | 滑雪機 p8–10 |
| 收尾 | 判讀說明與結語 | 無圖 | 母體口徑＋可觀測性偏差＋資料限制＋**三條編號結語** | 滑雪機 p11 |

### 🔴 為什麼是這幾頁——每一頁都通過了「不重複」檢查

「綜合兩份範例的優勢」不等於把兩份的頁數相加。2026-08-10 逐項檢查後的取捨：

| 原本兩頁 | 處置 | 理由 |
|---|---|---|
| 執行摘要 ＋ 研發建議 | **合併成建議一頁** | 都是「報告總結」。發現本來就是建議的依據，寫進「依據」欄比另開一頁更緊 |
| 技術分類全景 ＋ 技術主題表 | **合併成主題演進圖** | 同一份主題資料換個軸而已。「件數≠多樣性」的判讀併進該頁文字 |
| 功效主題表 ＋ 機會評估四象限 | **合併成機會四象限** | 象限圖已含件數與家數，比表格好讀 |
| 主題表格（正文）＋ 附錄總表 | **只留附錄** | 表格的價值在回查，不在正文 |
| 申請人排名 ＋ KP 象限 | **兩頁都留** | 不是重複：象限看**定位**（廣度×深度），排名看**數量與組成**（單獨／共同／轉讓）。少了排名就看不出量體 |
| 申請人年度矩陣 | **留** | 唯一能看出各家**進場時序與連續性**的圖，其他頁都是靜態切面 |

⚠ 範例中**沒有**的頁型不要自己加回來：裸圖表頁（一張圖＋模板三句）、
IPC/CPC 只有一兩根長條的頁（分類 <3 種即整頁不出）、與其他頁重複口徑的排名頁、
**兩張不同主題的圖硬合在一頁**（讀者不知道該看哪張）。

## 三、數字口徑（硬護欄）

寫作時三類資訊、三種待遇：

1. **標題級統計**（總件數、各分類件數、家數、占比、年度數字）：
   一律以引擎的 `report_data.json` 為準，**不得自己重算後改寫**。
   自查結果與 report_data 不一致時，以 report_data 為準並在 evidence 記下差異。
2. **專利層事實**（某案的日期、狀態、權利人、請求項內容、同族清單）：
   用 `query_patents.py` 查回來**直接引用**，並在 evidence 記 patent_id。
3. **衍生判斷**（技術分期、專利牆、空白區、KP 定位、演進主線）：
   這是你的分析，**必須附依據**——引用了哪些數字、讀了哪幾件專利。
   沒有依據的判斷寧可不寫。

## 四、寫作品質細則

- 機構層用詞：描述技術寫到**具體機構／手段**（零件名＋作動方式，例如
  「〈零件〉帶動〈零件〉達成〈功能〉」），不寫抽象類名（「阻力技術」「安全技術」）
- 具體人事時地：點名申請人、點名年份、點名件數；「多家廠商近年積極布局」這種句子＝廢話
- 主題代碼（T001 等）與內部欄名（report_key、topic_key）不得出現在任何頁面
- 簡體字不得出現（來源欄位若是簡體，轉繁後使用）
- 不確定的推論用「可能／傾向／需確認」，並說明確認方法
- 每頁文字量以範例為上限：要點框 3–5 條 bullet，每條一到兩行；不寫成段落牆
- 🔴 **專利號只出現在附錄**（2026-08-10 使用者定案）。正文任何一頁——尤其 KP 深入——
  都不放號：一個號佔掉一行卻不告訴讀者任何判斷，那一行拿來寫機構層內容價值高得多。
  要回查的人翻附錄。

### 🔴 濃縮的判準：拿掉它會不會少一個判斷

「濃縮」不是把版面空出來，是**讓每個區塊寫的都是最有價值的內容**（2026-08-10 使用者定案）。

逐條自問：**這句話拿掉，讀者會少掉一個判斷嗎？**

| 拿掉不會少判斷 → 刪 | 拿掉會少判斷 → 留 |
|---|---|
| 圖上讀得到的數字（排名、件數、佔比） | 圖上看不出的機構層手段 |
| 專利號、主題代碼、內部欄名 | 「這條路線與另一家不衝突」這種關係判斷 |
| 「多家廠商積極布局」這類無主詞句 | 「這格空是因為專利資料無法區分，需做痛點調查」這種**限制說明** |
| 同一件事換句話再講一次 | 具名對象＋數字＋所以呢 |

⚠ 空出來的位置要**補更有價值的內容**，不是留白。一頁只剩三句話卻很「乾淨」，
那不是濃縮，是內容不足——該把那頁併掉。
