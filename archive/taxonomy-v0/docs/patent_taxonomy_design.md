# 專利多維度分類樹設計（Box 為主 + LLM 輔助）

狀態：設計中（PoC 前）。本文件是「AI 產生分類建議、人工確認版本化」功能的分類樹核心設計，與侵權比對分開。靈感來源見 `obsidian learn/專利學習/分類樹研究/`（TaxoGen / TaxoExpan / TaxoCom / BoxTM / TaxoAdapt / BoxTaxo）。最後更新 2026-07-10。

---

## 1. 目標與定案總覽

- **純文本驅動**：不用 IPC/CPC 建樹（IPC/CPC 可當**評估外部參照**）。
- **多維度**：問題／手段／功效／應用／元件；**MVP 只做 手段 × 功效**（技術功效矩陣）。
- **每維一棵樹、共用同一 box 空間**；節點＝片語級 box；**小版本只增不減、大版本受控重構**（見 §7.2）。
- **Box 為主、LLM 為輔**。

```text
資料      純文本；專利文字為【英文】，不需翻譯
維度      MVP 手段×功效
抽取欄位  手段=独立项 / 功效=效果 摘要（詳見 §1.1）
嵌入      frozen 英文 PatentSBERTa（片語只嵌一次）→ MLP projector 轉 box（見 §2.1）
訓練路線  主線 B（骨架邊+共現雙訊號）；C（純共現）待語料擴充後當對照；A 已捨棄（見 §2.1）
推論      排序式掛節點（argmax R_a＋margin，同分取體積小）
門檻      分位數校準（τ_novel=95% 起手、per-node、每版重校）
語料      正式=力山自有 525 筆（TextDown_20260710）；407 園藝檔=分析集；訊號語料延後(WIPS 匯出)
部署      離線訓練 → 凍結 artifact → 上線；正式庫空、前端有樹骨架
動態      box 原生 completion（TaxoCom 為精神啟發，不移植其流程）
處理時機  每次有資料就分（即時 streaming）
```

## 1.1 資料來源與欄位（2026-07-10 實測驗證）

抽片語**按維度取欄位**，不再是「標題+摘要」。

**正式語料（2026-07-10 定案）**：`data/raw/TextDown_20260710_pm023742_525.xlsx` —— **力山自有專利組合 525 筆**（鋸床/跑步機/磁磚切割/健身器材；CN 306＋US 208＋EP 8＋其他 3）。

- 本檔為 26 欄精簡匯出：MVP 欄位齊全；缺 `解决课题 摘要`/`所有权利要求`/引用欄/IPC 稀疏(205/525) → **建議日後在 WIPS 重匯全欄位版**（非 MVP 擋路項）。
- 空值缺口：独立项空 14、效果摘要空 26 → P1 flag，該維度缺標籤由多標籤設計容忍。

**分析集（不重要）**：`wips_lishan_2026-07-01_001.xlsx`（407 筆、148 欄，園藝工具領域檢索、非力山專利）——欄位語義驗證（下表依據）在此檔完成，兩檔同為 WIPS 欄位、語義相同；此檔與正式語料零重疊，之後可當獨立分析集或訊號語料的一部分。

| 維度 | 欄位 | 依據 |
|---|---|---|
| **主題**（第三分面） | `独立项[...]` 的**前言**（claim preamble） | claim 法定三段式：前言=標的物（A brush cutter）；規則切分（編號後、轉折詞前）；MVP 當 metadata＋前端第一層導覽，**不建樹不訓 box** |
| **手段** | `独立项[KR,JP,US,CN,EP,IN]` 的**主體** | 逐字來自 claim 全文（406/407 每項都對得上）；`\|` 分隔全部獨立項；與 `独立项数量` 內部一致 404/407；**一欄拆兩用**（前言→主題、主體→手段） |
| **功效** | `效果 摘要[US,EP,PCT,JP,KR,CN,TW]` | claim 全文 `improves` 出現 **0 筆**（效果摘要 404 筆）→ claim 不寫功效 |
| 問題（之後） | `解决课题 摘要[...]` | claim 與 abstract 的 `problem/solve/issue/difficulty/drawback` **各 0 筆** |
| 應用（之後） | `技术领域 摘要[...]` | — |

**排除的欄位（都有實測依據）**
```text
主权项            只裝第一個獨立項；前50筆有 33 筆(66%)獨立項數>1 → 會漏
所有权利要求 全文  從屬項佔 56% 篇幅、多帶 +64% 詞，但 Top50 幾乎全是幾何位置限定詞

解决手段 摘要      對其他獨立項特有技術詞覆蓋【中位 0%】；corr(獨立項數量, 長度)=0.084
                  只反映第一個獨立項 → 不用，連「種子」也不當
```

**其他已確認**
```text

```

## 2. 監督定位

```text
整體 = weakly-supervised   ← 維度標籤來自 WIPS 已分好的 AI 摘要欄位（資料供應商的 AI 標註）
建樹 = self-supervised     ← box + 聚類 + box 原生 completion，訊號全來自語料
```
- 判定慣例：整體監督定位取**最強的外部監督訊號**命名。維度（手段/功效/問題）**不是我們用 LLM 判的**，而是 WIPS 提供的分欄（`独立项` / `效果 摘要` / `解决课题 摘要`），屬**資料供應商的 AI 標註**（LLM-as-annotator 的一種）→ 整體仍是 weakly-supervised，不能稱 self-supervised。
- **LLM 不再標維度**（2026-07-10 變更）。LLM 只做：抽片語(+AutoPhrase)、消歧去重、節點命名、給長節點理由、解讀 pending 缺口 —— 全部**不進 box 訓練損失**。
- **不採用**「LLM 生成 is-a 對餵 box 訓練」（會把外部監督灌進 box 損失，破壞建樹 self-supervised）。
- 每維度內部的樹（box 學階層）訊號全來自語料 → self-supervised。詳見 `../../obsidian learn/專利學習/分類樹研究/embedding_research_directions.md` §8（LLM-as-annotator / distant supervision）。

## 2.1 Box 訓練路線（2026-07-10 定向）

**共通轉換器（任何路線都必須有）**
```text
片語 → frozen PatentSBERTa → n ∈ R^768
center c = MLP_c(n)；offset o = exp(MLP_o(n))（保每維>0）→ box=(c,o)
初始化：c 用降維後的 SBERT 向量、o 給小常數（起手=帶小盒的點雲）
理由：BoxTM 的自由參數盒綁死詞表，新片語沒有盒子 → Online loop 必須靠 projector 泛化
（架構出處：BoxTaxo §4.2 Eq1-2；差異：BoxTaxo 的 BERT 是 fine-tune，我們 frozen —— 未驗證設定）
```

**路線 A（純骨架邊）：已捨棄。** 原因＝迴音室：骨架由 SBERT 向量聚類產生，joint loss 飽和目標把骨架刻進 box → box 空間 ≈ 骨架的幾何複製品 → 精修重聚類只是回聲。發現力天花板 = SBERT 向量幾何；且這**違背 BoxTaxo 自己的論點**（向量相似度表達不了 is-a）。v1 刻錯的結構在只增不減治理下近乎永久。→ 只留作 PoC baseline，不當路線。

**路線 B（骨架邊＋共現雙訊號）★ 主線，407 可跑**
```text
① 多組聚類（不同 K/種子）→ 只取【共識高的邊】當骨架 v0；低共識區留白
② 訓 box：L = joint loss（骨架邊：Lg±+Lp±，邊按聚類信心加權、不確定邊軟目標 0.9/0.1）
            + λ·共現 CE（R_a(w_i|w_j) 對齊 P(w_i|w_j) —— 獨立於骨架的發現訊號，防迴音室）
            + Lr 正則（防塌陷）
   訓練配對：⟨片語→葉節點⟩⟨子節點→父節點⟩正對 + 兄弟/叔堂負對（BoxTaxo 採樣法）
③ 兩訊號打架 → 【衝突偵測＋降權】（定案）：
   骨架說兄弟、共現暗示包含 → 該骨架邊降權/摘掉，並記錄成「骨架糾錯清單」
   （衝突點=發現點；搭配 λ 排程：先骨架後共現）
④ box 空間重聚類（重疊圖+Leiden）修骨架 → 再訓（迭代 1~2 輪）
⑤ LLM 命名 → 人工確認 → 凍結 v1；v2 起改用【確認過的真樹邊】訓練（訊號逐版變乾淨）
註：407 階段共現稀疏 → λ 初期小；語料擴充後加大（防鎖死效果隨語料變強）
```

**路線 C（純共現，box 從零長樹）：對照組，需語料擴充到幾千件**
```text
L = 共現 CE（階層發現唯一來源）+ 包含 max-margin（對訓練中重聚類的「當前樹」約束，
    box 與樹共同演化）+ 正則；照抄 BoxTM 早停 trick（後期停止重聚類）
硬前提：共現訊號量=語料量 → 專利要重新找過（幾千件；AutoPhrase 統計品質同步變好，
        成本≈撈資料+AutoPhrase，LLM 幾乎不動）
零梯度：選 Gumbel 軟盒（丟 hard box 可解釋性）或自加幾何項（無背書）—— 待 PoC 定
```

**PoC 評估（2026-07-10 調整：baseline 對照先擱置，之後有時間再做）**
```text
現在：跑 B（正式語料）→ 直接用 §10 指標評估這套分類的效果
      絕對數字的參考錨點：① 人工看樹（節點合理性、命名可讀性）—— 真正的放行閘
                        ② reconstruction acc 可粗略對照 BoxTaxo 報的 82.2/60.9%（不同資料，僅參考）
                        ③ v1→v2 跨版比較（相對進步）
擱置：Baseline 0(SBERT+聚類無box) / 1(BoxTM 原版) / 2(BoxTaxo 原設定) —— 之後有時間再玩
      （骨架 v0 本來就是 B 管線的副產物，日後要補 Baseline 0 幾乎零成本）
並行：撈訊號語料；到位後補 C 與 B-大語料版
```

**推論與門檻（兩路線共用，定案）**
```text
掛節點  排序式：argmax R_a ＋ 贏第二名夠 margin；同分取體積小（BoxTaxo 推論規則）
門檻    分位數校準：τ_novel = 已知片語 max R_a 分布的第 5 百分位（95% 起手）
        → 已知片語被誤判 novel 的比率 ≈ 5%（誤報率可控；recall 無保證，量大可調 99%）
        per-node/per-深度校準（大盒節點 R_a 天然偏高）；每版重校；τ_class 同法從真邊分數分布定
註：hard box + joint loss 照樣配分位數推論 —— 門檻校準與盒子軟硬是兩個獨立決定
```

## 3. 名詞定義

```text
片語 box    每個唯一片語一個 box(center+offset)；體積=語意範圍；共用詞庫、只嵌一次
概念節點    分類樹節點 = 一群片語(其一當代表，LLM 命名)
維度        MVP 手段/功效；每維一棵樹、共用 box 空間
R_a         box 非對稱包含度 R_a(b|n)=Vol(b∩n)/Vol(b)，b 完全被 n 包住時=1；表 is-a
文檔 box    (選配) 專利=其片語 box 的聯集；僅用於整件相似/檢索
```

## 4. 部署與運行模式

### 4.1 離線訓練 → 凍結 artifact → 上線
```text
artifact（同版本打包，像 LLM checkpoint）
  ① Box Projector 權重（+ encoder 版本；純 frozen 則只記版本號）
  ② 分類樹結構（節點、box 座標、階層、version）
  ③ 片語詞庫 + 片語→節點對照表
  ④ 門檻/超參配置
  ⑤ LLM prompt templates + 維度定義 + 輸出 JSON schema + LLM 模型版本號
LLM 本體不記權重（外部 API、不 fine-tune）
```
- 上線 = 流程(pipeline) + 權重資產(①②③④⑤)；樹屬「權重那一側」，不是使用者資料。
- **正式庫空**指沒有「使用者專利資料」，不是沒有樹。

### 4.2 前端顯示（2026-07-10 定案）
```text
① 顯示 = 只有【使用者資料】掛到的類別（實字、計數、可點、可展開）
② 框架有、使用者沒資料的類別 → 一律不顯示（連灰字都不出）
③ 虛字 = 說明性文字，不是類別內容：
   初始空狀態「上傳專利後，系統會自動分類至技術/功效類別」
   → 使用者知道「有訓練好的座標系存在」，但座標系內容不露出
④ 訓練專利任何情況都不出現（無「範例層」—— 已否決，避免與使用者資料混淆）
⑤ 空白點 = 使用者自己的手段類×功效類交叉中的空格（行列全來自使用者資料）
   —— 全域座標系只在幕後當分類器，使用者看到的一切都源自自己的資料
```

### 4.3 成品視圖（技術功效矩陣）
```text
手段樹、功效樹「各自獨立」存；靠專利(多標籤)當橋樑連結
技術功效矩陣 = 手段節點 × 功效節點 的「即時交叉 view」：
  格(手段A × 功效B) = 有手段A的專利 ∩ 有功效B的專利
  不預存固定矩陣；資料量大用 materialized view 快取
「點某技術主題看它的功效分布」= 即時交叉呈現，底層仍是兩棵獨立樹 + 專利連結，
  不是把功效存成技術的子節點（否則功效重複、只能單向、加維度就爆炸）
樹可展開(大類▸子類▸片語)；一件專利多標籤(出現在多格)；每格/節點標專利數

矩陣的產出時機（2026-07-10 定案）：矩陣是【報表產物】，不是常駐畫面 ——
  使用者勾選要分析的專利 → 跑報表 → analysis_runs 快照選集
  → 矩陣就地計算（行列=選集的手段類×功效類；空白點=選集內的空格）
  → 輸出 HTML/Excel/PPT → analysis_outputs / export_runs 留追溯
  （復用既有七支報表的同一條 app_layer 追溯鏈；選集幾十~幾百件現算即可，不預存）
```

### 4.4 分類實例：大分類 + workspace（2026-07-10 定案）
```text
大分類（global）   所有入庫專利自動對正式樹分類；長節點走既有治理
workspace（fork）  使用者圈一批自己的資料，從【乾淨的 frozen artifact】開始套用分類
                   （fork 基準=乾淨 artifact，不是大分類當前狀態）
                   novel/pending/長節點/批准 全部只作用在自己樹上，互不污染
實作               copy-on-write：base 節點唯讀共用一份，每個 workspace 只存
                   自己長的節點(scope='grown')與分類結果（tax_* 表加 instance_id）
模型               encoder+projector 全域共用 frozen；「樹」才是多實例的

rebase（機制保留）：乾淨 artifact 升大版本 v2 時，workspace 可選時機搬到新 base ——
  ① grown 節點用 v2 模型重投影、依 lineage 掛到 v2 對應位置
  ② workspace 專利全量重跑 → 差異清單 → 使用者確認 → base 指標改 v2
  為什麼要有：base 綁著模型(projector/box/門檻)，停在 v1 = 系統永遠養舊模型、
  繼續背 v1 已知的錯、分歧債越滾越大；但 rebase 時機給使用者挑（分析口徑凍結權在他）
  現實約束：舊 base 設支援期（如只養前一個大版本），到期前須 rebase
```

### 4.5 主題分面（2026-07-10 定案）
```text
主題（claim 前言：brush cutter / trimmer / a method of...）=【第三分面】，與手段/功效正交
不當手段樹/功效樹的父層 —— 否則同一手段跨產品要複製 N 份、只能單向查、加主題樹就翻倍
（跟「功效不塞進技術下面」同一個理由）
UI 上主題呈現為第一層導覽=「篩選」：點主題 → 篩出該主題專利 → 顯示其手段/功效分布與矩陣
（= 即時交叉，同矩陣報表機制，多一個主題篩選條件）
MVP：前言規則切出存 metadata（零成本，不建樹）；之後升格正式分面時與「應用」維
（技术领域 摘要）合流：前言=標的物、技术领域=場景
專利識別（定案）：patent_no = COALESCE(授權公告號, 未審查的公開號, 申請號)
  對外顯示/報表用它，隨資料更新升級顯示（方案 a）；內部串接仍用不變的 core_layer.patents.id
```

## 5. 完整資料流

### ① 離線訓練（bootstrap v1，主線=路線 B）
```text
代表性語料：手段取 `独立项` 欄、功效取 `效果 摘要` 欄（各維度分別抽，維度由欄位決定）
→ 抽片語：AutoPhrase 為主（可擴展、訊號語料不需 LLM）；正式集才加 LLM 補漏+消歧去重
→ frozen PatentSBERTa 嵌片語 → box projector 投影成片語 box
→ 路線 B 訓練（見 §2.1）：共識骨架邊 joint loss + λ·共現 CE + 衝突偵測降權
  → box 空間重聚類修骨架 → 迭代 1~2 輪
→ LLM 命名節點 → 人工確認 → 手段樹 / 功效樹(v1)
→ 分位數校準門檻 → 凍結 artifact
```

### ② 運行（一套流程，每次有資料就分）
```text
新專利 → 各維度從對應欄位抽片語(AutoPhrase+LLM，不判維度) → frozen encoder → 片語 box
→ 對所有節點算 R_a → 排序式判定（門檻皆為分位數校準值，見 §2.1）：
  ├ max R_a ≥ τ_class 且贏第二名夠 margin → 掛該節點（同分取體積小=最細粒度）
  ├ τ_class > max R_a ≥ τ_novel           → 灰色地帶 → pending（待 LLM/人工）
  └ max R_a < τ_novel（比 95% 已知片語都差）→ novel → pending pool
→ 專利 = 片語們的節點聯集（多標籤、各維度）→ 寫使用者資料範圍；不改樹
```

### ③ pending 重評（每次資料、增量；每半年全量校正）
```text
新 novel + pending 舊 novel → box 空間聚簇(見 §7) → 算支持度
  ├ 樹已擴充能掛 → 歸位
  ├ 支持度達標   → 建議長(見 §6)
  ├ 仍稀疏       → 續 pending
  └ 噪聲         → 淘汰
增量重評：新片語只碰「box 空間重疊(R_a>θ_edge)的 pending 區域」，只重跑受影響社群
全量校正：每半年對整個 pending pool + 樹全量重評一次(防增量漂移)
```

### 5.1 獨立項切分與格式偵測（2026-07-10 定案）

```text
切分流程：独立项 欄 → 「 | 」切各獨立項（實測 404/407）→ 去開頭編號（1. / 6. / 14.）
        → 容錯格式偵測 → 前言(主題) ｜ 主體(手段抽取來源)

格式策略三層設計（理論完備、表驅動、LLM 兜底）：
① 理論格式表（照教科書寫全，不隨手上資料伸縮）：
   轉折詞：comprising/including/containing/characterized by(開放)、consisting of(封閉)、
           consisting essentially of(半封閉)、composed of/having(依脈絡)
   標的類型（前言頭名詞→主題標記）：裝置/方法(A method of)/系統/組成物/CRM/
           用途項(Use of,無轉折詞,專屬策略)/product-by-process/套組/means-plus-function
   結構：單段式、兩段式 EPC(characterized in that)、Jepson(In a...the improvement comprising)、
         Swiss-type、Omnibus(標記後丟 LLM)
   陷阱規則：Markush「group consisting of」排除、多重轉折取第一個主轉折、
             長 token 先比、從屬項格式混入→資料異常 flag
② 表驅動+容錯（不寫死）：pattern 清單放【設定檔】非程式碼；大小寫/英式拼法
   (characterised)/動詞變體(comprises/which comprises)/標點空白全容錯；
   新變體=加一行設定，不改程式；設定檔變更需人工批准+版本化
③ 全部套不進 → LLM 切（兜底）：prompt 附格式理論表 → 輸出 JSON{preamble,body,format_guess}
   → grounding 驗證(重組≈原文子字串) → flag='llm_split' → 進抽樣人工檢清單
每個獨立項永久保存 format_tag（可追溯、可統計；裝置/方法標記直接餵主題分面）

上線監控（機器量、LLM 診、人拍板 —— 與長節點治理同一權責模式）：
  腳本：llm_split 率/格式分布/grounding 失敗率/從屬項混入 → 定期算；門檻警報=規則觸發
  LLM(GPT 當監工，換家防循環)：讀 fallback 樣本歸因新變體 → 草擬 pattern 候選(附例句)、
      抽查規則層切分品質、寫週期診斷報告
  人工：批准 pattern 合入設定檔（LLM 不得自動改 —— 切分行為漂移=下游全變+不可重現）
  閉環：llm_split 率升 → LLM 歸因 → 人批 pattern → 長尾「畢業」回規則層
```

### 5.2 抽片語管線規格（2026-07-10 定案）

**正式語料（力山 525 件）：兩件套為核心，備援掛載**
```text
MVP 管線：NP chunking（候選主力，單篇可跑、零訓練）
  → 規則清洗/正規化/字面去重
  → LLM 每件專利一次 call（①補漏：動賓型功效、關係型手段 ②裁決候選 ③標同義組，輸出 JSON）
  → grounding 子字串驗證 → 向量去重
理由：LLM 閘門橫豎每件一刀（call 數不因候選源多而減），候選層 recall 夠即可
掛載備援（架構留位、抽查發現問題才啟用）：
  AutoPhrase → 訊號語料到位後訓好套上（第二候選源）
  C-value    → 嵌套收得亂時啟用（嵌套裁決）
  KeyBERT    → 雜訊多到 LLM 裁不動時啟用（預過濾）
啟用判準 = 20 件人工片語抽查（本來就要做的品質抽查）
```

**片語粒度（2026-07-10 定案）**
```text
L2 基本技術片語(electric motor) + L3 複合概念(rechargeable battery pack) 為主
嵌套：收（L3⊃L2 嵌套對=天然 is-a 訊號，box containment 最愛；去重層明確「包含≠重複」）
L4 元件+關係(motor mounted within the housing)：LLM 選擇性抽（只抽判定為發明關鍵的），守 grounding
L1 單詞/L5 整主體：不收
```

**功效維主從反轉（欄位性質所迫）**
```text
效果 摘要：164 字、模板化、動賓型(improve operability) → AutoPhrase 統計算不動
→ 功效維 = LLM 抽為主（grounding 照守）+ 依存句法動賓抽取(規則驗證)
手段維 = 候選層為主、LLM 收尾（正常主從）
```

**清洗與去重**
```text
清洗：claim 套語表(said/wherein/plurality of…)從片語邊緣剝除；效果模板框 regex 剝殼；
     正規化(小寫/單複數/連字號/空白)；清單=種子+資料驅動(高文檔頻疑似套語→LLM審→人批)
去重三段式：①字面層(正規化後相同→自動合併) ②向量雙門檻(>τ_high 快速確認、
     τ_low~τ_high LLM 判技術同義、<τ_low 獨立；嵌套對排除在合併外)
     ③canonical=最高頻形態、其餘入 alias 表(可回溯可反悔，un-merge 只在大版本)
增量：新片語→精確比對→最近鄰→雙門檻；先到先當 canonical，換人只在大版本
```

**訊號語料（非必須，平行任務）**
```text
定位：加強包非地基 —— 用意=共現統計(路線B λ 項/BoxTM word-level 概念)+訓 AutoPhrase
     MVP 可不做（λ=0 起跑）；要不要做等 PoC 的樹說話（被骨架鎖死→該撈了）
處理：全自動零 LLM：AutoPhrase 自訓 → 分數 cutoff+統計體檢(套語率/詞性/長度/頻率)
     → 只拿過關片語算共現；文檔蒸餾後不進訓練不進系統
QA 防循環：詞庫重疊率只用【非 AutoPhrase 來源】子集當驗證組（來源溯源本來就存）
     消融(λ=0 vs >0)=驗「共現機制該不該存在」，不是驗資料 —— 資料品質由上游四道關卡定
儲存：冷存目錄 data/signal_corpus/batch_*/（raw 原樣+metadata 記查詢式）
     GPSS XML 優先（Excel 有 32,767 字元截斷風險，自家 claim 已見 30,003）
```

## 6. 長節點決策鏈（核心）

```text
box 訊號(novel：R_a 低) → 進 pending → 累積
  → 支持度達標(見 §7) → box 訊號說「該長」
  → LLM 產出理由(這是什麼技術/為何新/建議命名/長 or 合併) → 建議卡
  → 傳給使用者 → 使用者說長 → 才真的建節點(進 v2)
```
- 角色：**box=偵測觸發、LLM=給理由(不決定、不進損失)、使用者=唯一 commit**。
- 人工/使用者確認是**唯一 commit 點**（AI 不自動改正式樹）。

### 6.1 不長的回落（不影響 precision）
```text
使用者決定不長 → 用 τ_fallback 在既有樹上從 leaf 往 root 找「最深的、box 還能包住此片語的節點」
  ├ 某 leaf 包得住(同義/變體) → 合併進該 leaf
  ├ 只有父盒包得住            → 暫掛較粗父節點
  └ 全都包不住                → pending
原則：「可見的粗粒度/pending」換掉「隱藏的錯節點」；片語不懸空、不硬塞錯節點
     否決多半是攔截訊號誤報 → 對品質是保護
```

### 6.2 novel（質）vs 支持度（量）
```text
novel     單一片語「新不新」：box R_a 低(對所有既有節點都包不住) → 送 pending
支持度    一群 novel「夠不夠成一類」：n_min(片語數) + m_min(跨專利數) + 簇緊緻度
          跨專利數 m_min 最關鍵：防「一件專利自己刷出一個假節點」
```

### 6.3 pending 的用意 + 生命週期
```text
用意：保 precision(不硬塞錯節點) + 成長種子(攢相似 novel 到夠支持度) + 覆蓋缺口訊號(可診斷)
生命週期：框外→pending →(累積達支持度)建議長 /(樹擴充)歸位 /(續稀疏)留 /(噪聲)淘汰
是「有進有出的流動池」，不躺著、不無限膨脹
```

### 6.4 領域外資料：拓撲隔離 + pending 側樹（2026-07-13 定案）

情境：使用者的資料領域大幅偏離訓練語料（例：525 筆＝鋸切/健身/磁磚，進來的是無人機飛控）
→ 大批落 pending。此時**不硬塞主樹**（會汙染頂層維度，且只增不減治理下近乎永久），
改讓 pending 自己長結構，成熟才接進森林。

```text
【前提：拓撲隔離，不是空間隔離】★ 關鍵
  同一個 encoder(frozen) + 同一個 projector + 同一個 box 空間，但允許多個根：
      box 空間（唯一）
        ├ root_A  電動工具（訓練語料長出的主樹）
        ├ root_B  無人機動力    ← pending 累積夠了才長出來
        └ root_C  e-bike 動力
  隔離的是「樹的拓撲」，不是「box 空間」。側樹若自己訓一套 projector，座標系不可比，
  R_a（包含判斷）算不出來 → 匯整只剩「整棵重訓」或「無理論依據的硬對齊」兩條死路。
  空間共用 → 側樹誕生即與主樹可比較 → 所謂「匯整」只是接上拓撲，box 座標一個都不用動。

【pending 側樹的循環】
  進池即歸群（同 box 空間最近鄰）→ 定期 Leiden 重聚類 → LLM 命名
  → 過【顯示門檻】才在前端長成節點 → 過【升格門檻】才進主樹凍結

【兩道門檻】（取代「前端標示暫定」的做法 —— 使用者定案：前端不出現「暫定分類」字樣）
  顯示門檻(低)  群集 ≥ n_show 筆且 LLM 可穩定命名
                → 一旦顯示：節點 ID 固定、父子拓撲只增不減（與正式節點同等待遇）
                → 前端呈現為正常分類節點，不加任何「暫定」標記
                未達門檻的資料落「其他」桶，不長節點、不給名字

  【名稱可改，禁止的是「系統自動改名」】
    可變   顯示名稱 —— 人工隨時可改（LLM 命名常不合公司內部術語），
           舊名進 alias 保留可回溯；改名不動 ID，既有引用照常有效
    不可變 節點 ID、父子拓撲 —— 對外引用/Report/API 靠 ID，發出去就是承諾；
           節點不刪、不換父（會打斷引用），加子節點不受限
    禁止   重聚類時 LLM 覆蓋既有節點名稱（無聲漂移＝使用者眼中的「系統壞了」）；
           LLM 只對【新生成】的群集命名
    （canonical/alias 與片語去重同一套邏輯：canonical=當前正式名、alias=歷史名）
  升格門檻(高)  ≥ n_min 筆 + 能撐出 ≥2 層結構 + 與主樹任一節點 R_a 皆低於 τ_novel
                （第三條防「其實是既有節點的變形卻自立門戶」）
                → LLM 建議卡 → 使用者確認 → 接進森林、凍結進 v2

【後台差異（前端不可見）】
  未升格節點：無對外穩定 ID、不進 Report、不可被外部引用 —— 寫死在 API 層，不靠 UI 提醒
  代價：顯示門檻一過即 canonical 固定 → n_show 不能太低，否則鎖進不穩的聚類結構
        n_show 待 PoC 觀察 pending 實際聚類行為後校準（列入 §11 待決 A）
```

## 7. 動態擴充 = box 原生 completion（TaxoCom 為精神啟發）

取 TaxoCom 的**精神/範式**（completion：frozen 樹上做 novelty-based 補全、就地補位、自動粒度），用 box 原生實現，**不移植其球面嵌入與 local re-embedding**。

### 7.1 自動定子數（把一群 novel 聚成幾個新子節點）
```text
方法   box 重疊圖 + Directed Leiden 社群偵測
邊     有向、加權，權重 = R_a(A|B)  ← 保留非對稱(方向=包含/父子)，不對稱化
θ_edge R_a ≥ θ_edge 才連邊；中等起步，精確值待資料校準
K      社群數自湧現 = 自動定的子節點數
附帶   有向邊方向順便標出父子層級 → 聚類與層級一步到位
```
- 選 Leiden（Louvain 改良版，修掉不連通社群、品質更穩、有有向版），配「每次即時 + 增量重評」順。

### 7.2 版本治理（大/小版本，2026-07-10 定案；取代「樹只增不減」）

判準一句話：**舊分類結果需不需要重新解讀？需要 → 大版本；不需要 → 小版本。**

```text
小版本 v1.1→v1.2（滾動、頻繁、逐筆批准=建議卡）
  允許：加新節點(使用者批准的 novel)、詞庫加片語、門檻重校準、
        節點標 deprecated / merged-into 別名（軟棄用：不刪、分類自動轉址）
  不允許：動結構、動模型
  舊分類：全部照舊有效

大版本 v1.x→v2.0（事件觸發、整包審查）
  允許：受控重構 —— 拆/併/搬/改名（TAXMORPH 四操作）+ box 重訓（用確認過的真邊）
        + pending 全量重評 + encoder/λ 等模型調整（解凍、加大共現權重只在大版本做）
  配套：節點血緣表(lineage) → 舊分類自動重掛；人工整包批准後才發布
  觸發：半年全量校正發現健康惡化(錯分率/pending 堆積/節點冗餘超標) /
        語料大擴充(407→幾千件) / 加新維度(問題、應用)
```
- 半年全量校正 = 大版本的「體檢」：發現問題不直接改，觸發「要不要開大版本」的決策。
- 這解掉「v1 刻錯近乎永久」的疑慮：錯誤可修，但要等大版本＋人工批准。
- **重跑策略（2026-07-10 定案）**：小版本不重跑（pending 歸位機制定向撿回相關片語）；大版本**全量重跑**＋產出「分類變動差異清單」給人工確認（800 筆規模=分鐘級）。
- workspace 的版本：輕量（只增＋軟棄用）；大版本發布後可選時機 rebase（見 §4.4）。

**大版本變差的三道防線（2026-07-10 定案）**
```text
防線1 發布前品質閘門（主力）：v2 候選 vs v1 同台比 —— §10 指標不得劣化超容忍值、
      gold set precision/Wu&P ≥ v1 才准過、差異清單人工抽查；不過=不發布，v1 照常服務
防線2 回滾：v1 artifact 不刪（支援期=回滾窗口）；tax_patent_class 帶版本欄，
      大版本重跑是【寫新版列】非覆蓋 → 回滾=版本指標指回 v1，零重算
      workspace rebase 前保留原分類快照（回滾用）
防線3 灰度：v2 過閘門後先讓 global/自願 workspace 用 → 看線上訊號(novel 率/pending 堆積)
      → 穩了才建議全面 rebase（workspace 逐個搬=天然金絲雀）
```

            （手段=claim、功效=效果 摘要）；AutoPhrase 抽片語算共現；不入正式庫
gold set    30~50 件：LLM 預標註起草 → 人工逐筆審核簽核（LLM 不能定案，避免循環評分）
分類實例    大分類(global) + workspace fork(乾淨 artifact 起點, copy-on-write, 可 rebase)
矩陣        報表產物（使用者選集 → analysis_runs → 就地交叉計算）

## 10. 評估方案（可腳本、v1→v2 可比）

```text
① 樹結構品質(免標註)：reconstruction acc ★先做 + containment/volume 單調性 + coherence(NPMI) + diversity + 單子節點率/冗餘
   —— 量「結構自洽」不量「語意正確」：語意全錯但幾何完美的樹可拿滿分 → 必要非充分
② 分類準確：人工小批 gold 的 precision/Wu&P + 相似專利→相近節點一致性 + LLM-judge
   —— 三層分工：指標量結構(守門) / LLM 對照量語意(放大規模) / 人工 gold 定真偽(錨點)
   —— 防循環評分(2026-07-10 定案)：管線 LLM=Claude(既有 AI Service)；
      評估/裁判與 gold set 起草=GPT(另一家)。裁判先用人工 gold 驗一致率(>85%)才放大到全庫
③ 動態/覆蓋：coverage / novel 率 + LLM 解讀 pending → 覆蓋缺口診斷
④ 下游/實用：defer 到整套產品建好才給人看
外部參照：IPC/CPC 當 sanity check(非真值)；v1 vs v2 對比證明動態有效
提醒：別只信內在幾何(TAXMORPH 洞見：好嵌入的樹 ≠ 好用的樹)；指標要可腳本重跑
```

**[已結案 2026-07-13] 樹的來源：維持「預置 frozen 樹」（路線 A 部署形態），不走「從零建樹」**
```text
起因：架構走到這裡，等於「上線那一刻已有既有樹」，與早期「從沒有固定的樹、用使用者資料長」

  ① 訓 projector：教模型「片語→box」的幾何（什麼樣的兩個技術片語存在包含關係）＝【能力】

現行設計把兩者綁死。若要「從零長樹」，只需交付 ①（frozen box 空間）＋空樹，
使用者資料全落 pending → 聚類長節點（即 §6.4 的機制，主樹為空的極端情況）。

定案：維持預置樹。理由＝路線 C 硬前提是語料幾千件，力山自有才 525 筆；
      客戶上傳幾十筆就想看到分類，空樹長不出東西，預置樹是唯一能給出結果的形態。

```

**①②分離的已知風險（2026-07-13 分析，切換路線前必讀）**
```text
★ 分離【不乾淨】：作用① 本身就攜帶作用② 的領域痕跡，不是「中性能力＋可換內容」。

A. projector 的幾何是領域內學的 → 換領域失真
   projector 學的是「此嵌入區域的向量關係 → box 該怎麼張」，樣本全來自電動工具片語對。
   新領域向量落在嵌入空間的另一區 → box 張太大(R_a→1，分不出階層) 或塌太小(R_a→0，全 pending)。
   Lr 正則強度是照訓練分佈調的，不會自動適應。

B. 門檻是分位數校準 → 空樹時無從校起（冷啟動）
   τ_novel=95% 分位、per-node —— 空樹沒有節點就沒有 per-node 分佈，只能沿用訓練端絕對值；
   新領域 R_a 分佈整體偏移 → 不是全 novel 就是全硬掛。偏偏發生在上線第一天。

C. 共現訊號把領域偏見烙進幾何（最隱蔽）
   路線 B 的 λ·共現 CE 來自訊號語料（十線電動工具）→ projector 權重裡已烙著
   「馬達↔轉子」「切割↔刀片」這類先驗。交付空樹 ≠ 沒交付偏見。

適用邊界：同一大領域內的子領域遷移（電動工具→其他機械/工具機）可行；
          跨大領域（機械→生技/半導體）必須用該領域語料重訓 projector，
          等於繞回路線 C 的「需要幾千件」硬前提。

可監控訊號（比「pending 高」更早更準）：
  訓練端記錄 box volume / R_a 分佈統計量 → 使用者端算同樣統計量 → 偏離超門檻即警示。
  pending 高只說明「分不了」；分佈漂移能區分【樹缺分支】(長側樹可解)
  與【幾何壞掉】(長側樹也沒用，box 座標本身是垃圾) —— 兩者處置完全不同。

連帶待決：projector 的訓練語料要不要擴大？
  只用 525 筆 → 幾何最偏鋸切/健身/磁磚，遷移力最差
  用訊號語料十線 8,722 筆 → 涵蓋無人機/e-bike/馬達/園藝，明顯更通用
  但現行設計定位「訊號語料蒸餾後不進訓練」——與此衝突。
  → 等 PoC 跑出 box volume / R_a 實際分佈再定，不憑空拍（列入待決 B）
```

## 12. 資料模型示例（設計參考，未建表；歸 derived_layer）

tax_instance        分類實例：instance_id, kind('global'|'workspace'), workspace_id, base_artifact

- 追溯：`source_field` 記片語來自哪欄 → 可回查 raw_records；raw/core 一律唯讀。
