# 分類樹 v0 歸檔（2026-07-13）

技術決策轉向：**骨架來源**從「多組聚類 → 共識邊」改為 LLM 生成（TaxoAdapt 路線），
分類樹另起爐灶。此處保存 v0 的全部產出與設計文件，**不是廢棄品**——
下面標 ★ 的內容新爐灶照樣要用，換掉的其實只有一小塊。

```text

  s3_cooccur.py       分維度共現統計：套語過濾＋頻率上限＋巢狀排除 → P(w_i|w_j) 落盤

  patent_taxonomy_design.md      設計文件（含 2026-07-13 新增的 §6.4、§11）
  patent_taxonomy_poc_spec.md    PoC P1–P8 規格
```

**腳本仍可執行**：歸檔後目錄深度不變（`poc/taxonomy` → `archive/taxonomy-v0/taxonomy`，
同樣兩層），腳本裡的 `../../data/...` 相對路徑照舊有效。

**資料不在這裡**：`data/raw/`（力山 525 筆）與 `data/signal corpus/`
（訊號語料 8,722／廢棄 6,916／備用 4,013）是資產，留在原位，新爐灶直接用。

## 轉向的理由（2026-07-13 討論結論）

```text
問題   聚類長骨架 = 歸納式方法 → 先天需要語料量、先天需要領域內語料
       → 使用者資料少（幾十筆）長不出樹；跨領域時 box 幾何失真
發現   八篇分類樹論文裡，唯一原生解掉這兩個約束的是 TaxoAdapt（ACL 2025）
       樹是 LLM 知識的產物，語料只決定「要長多細」
       實證：EMNLP'22 僅 828 篇 → 建出 62 節點的樹（力山 525 筆同量級）
       其多維度（task/method/…）＝我們的手段/功效；unmapped density ＝我們的 pending
接口   design 已定案「節點盒 = 標籤文字投影」→ LLM 生成的節點有名字就有 box，無縫接上
風險   ① 這個嫁接（LLM 骨架 + box 幾何）沒人驗過
       ② LLM 對專利術語的知識深度未知（論文跑的是 NLP/機器人領域）
       ③ 迴音室對象從 SBERT 換成 LLM，沒有消失 → λ·共現 CE 的角色升格
```
