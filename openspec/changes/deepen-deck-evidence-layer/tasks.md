# Tasks: deepen-deck-evidence-layer

⚠ **全批禁寫條件規則**（沿用 `add-deck-delivery-line` tasks 3b 的約束）：
任何形式鎖進閘門前，先過 design §1.2 的**三問**：

1. 不看語意能不能判定？（不能 → 建議形）
2. 🔴 滿足它的**唯一**途徑是不是把事情做對？（恆等式 → 安全）
3. 若有自由度：偏差是**多出來的**（可見，目視兜得住）還是**缺席的**（兜不住）？

⚠ 只問第 1 題會放行「每頁最多一句」這種鎖——那是 v5 的同型錯誤（design §4）。

## 🔴 小批紀律（2026-08-18 使用者裁決）

⚠ **有自由度的閘門一次只上一項，每項之後跑一次 4.2 目視迴圈**，確認內容沒有變薄
才上下一項。

理由：三問是**逐條**套用的，從未套用在多條的**交集**上。七條同時壓下來時，
CLI 最省力的共同解是**少寫**——而 §2.3 的「接不上依據就擋下」等於規格授權了丟棄。
同時上兩項，出問題時分不出是哪一條逼的；v5→v9 花了三個版本才找到根因就是這樣。

本 change 屬「有自由度」的批次：3.x 依據層級、3.7 行動對象、6.x 圖文一致、
8.x 表格適用情境。⚠ **零自由度的那些已移交輪一**
（`sync-report-contracts-and-palette`）：版型清單唯一定義處、結論頁閘門三個破口、
涵蓋率對帳、表格通用版型、路線圖併入結論頁、色票（見 5b）。

⚠ 本 change 未經使用者確認前不得 apply。

### 3.7 專利行動加受控對象（2026-08-18 使用者提出）

現況的自由度分配是**反的**：控制最嚴的欄（行動＝五選一）資訊量最低，
資訊量最高的欄（研發意涵＝自由文字）幾乎沒守。動詞是**分類**不是建議——
「佈局」沒有告訴讀者要做什麼。

```
現在：專利行動 = 迴避設計
改成：專利行動 = 迴避設計｜CN 121754862 獨立項第 2 要素
```

- [ ] 3.7.1 content schema：`action` 拆為 `verb`＋`target`
- [ ] 3.7.2 Red：`verb` ∈ `ACTION_VERBS`（既有）；`target` 必須來自引擎清單
      （`plan.json` 的 `claim_lookup.players[].patent_ids`，現成）
- [ ] 3.7.3 反向驗證：`target` 填一個不在清單裡的專利號 → 要紅
- [ ] 3.7.4 ⚠ 三問結果要寫進 design：Q1 過、**Q2 不過**（CLI 可從清單裡隨便挑
      一個填上就通關，是代理指標不是恆等式）、Q3 過（硬填的對象印在投影片上，
      看得見）。**保證的是「對象存在於資料中」，不是「指對了」**——
      指得對不對留給目視，與判讀句同一條紀律
- [ ] 3.7.5 上這一項之後跑一次目視，確認結論列數沒有因為「湊不出對象」而變少
      （若變少，涵蓋率對帳會顯示——那是輪一做的）
