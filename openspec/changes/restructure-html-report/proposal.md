# Proposal: HTML 報表版面與章節改版（restructure-html-report）

## Intent

把第二世代簡報的章節結構與解讀深度轉到 HTML 報表上，並重訂字級與圖表尺寸規則，
讓資料量大時不崩、資料量小時不佔版面。

## Why

PPT 與 deck 兩條交付線停產後，**HTML 報表是唯一交付物**，但它的版面規則是為
「一併餵給簡報」而定的，前提已經消失：

### 一、字級規則綁在一個已消失的消費者上

現行圖內字**不是 CSS 設的**——SVG 內寫死 15.1px，顯示字級由 `.chart-media` 的
`max-width` 反推（860px → 11.0px）。原始碼與 `decisions.md:3613` 都明訂
「**要改圖內字就改寬度，不要去動 SVG（動了會連 deck 一起壞）**」。

實測 deck 已全數退場：`deck_layout.py`、`svg_canvas.py`、`build_ppt.py` **皆不存在**，
全庫**無任何活 import**，殘留的 `deck` 字樣全在註解與 docstring 裡。

⇒ 該限制的唯一消費者已消失。**使用者 2026-08-21 明確同意 SVG 可改。**

⚠ 這件事必須先解開，否則本案自相矛盾：維持 SVG 15.1px 時，要讓圖內字顯示成 16px
需把圖撐到 `16 ÷ 15.1 × 1180 ≈ 1250px` 寬——**比原生 1180 還寬**，與「圖不要太大」
直接衝突。

### 二、圖表尺寸被控死

2026-08-13 的做法是「圖固定 400px 高」「`max-width: 860px`」。固定值對兩端都不對：

- **資料量大**（類別多、列數多）→ 擠在固定框內，標籤相黏、看不清
- **資料量小**（三五個類別）→ 佔滿固定高度，版面被稀疏的圖吃掉

### 三、章節與解讀深度停在第一世代形狀

第二世代的定案（`decisions.md:3010`、`3032`）是「依目標規劃章節與論證」與
「格式完全不固定，但必須講得出原因和結論」，這些**只落在已退場的簡報線上**，
HTML 側沒有承接。

## Scope

1. **字級**：`h1` 28px、`h2` 24px、正文與表格 16px、**圖內字 16px**。
2. **圖內字改由 SVG 字級直接決定**，不再由顯示寬度反推。
3. **圖表尺寸依資料量伸縮**，不設固定高度或單一 `max-width`；設下界與上界防兩端失控。
4. **數據表**：最精華的部分預設展開，其餘沿用現行收合方式。
5. **章節結構**依「怎麼做品質會提高」排序，不沿用既有固定頁序。
6. **敘述統計**新增為一節，位於結論之後、圖表章節之前，至少含各專利類型件數。
7. **整體限制說明**移至報表末尾並精簡；逐圖口徑註記留在原處。
8. **解讀深度**：技術趨勢的判讀要到位；行動建議**有可執行內容才寫**。

## Non-goals

- 🔴 **不新增任何「每則都必須有」的內容欄位或固定句型**——見 Confirmed Decisions 6。
- 不改解讀的取證、檢查機制與人工編輯（另案 `harden-report-narrative`）。
- 不新增品質判準：技術趨勢的深度由既有鎖四（統計數字）與鎖五（成因）涵蓋。
- 不改報表引擎、資料口徑、分群或 DB。
- 不改前端預覽頁的版面——**本案對象是後端產的匯出 `index.html`**。
- 不重新設計配色與字型（`Noto Sans TC` 維持既有定案）。

## Capabilities

### New Capabilities

無。

### Modified Capabilities

- `report-export`：HTML 報表的字級、圖表尺寸規則、數據表收合、章節結構與解讀深度。

## Impact

| 面向 | 影響 |
|---|---|
| `chart_runner` HTML 產生器 | 字級、章節組裝、數據表收合、`.chart-media` 尺寸規則 |
| `chart_sizing` | SVG 字級成為可調參數；`WEB` profile 的尺寸推導 |
| SVG 產生 | 內建字級由 15.1px 改為由設定推導 |
| 既有版面測試 | 量測基準需重建 |
| DB／API | 無 |

### Migration／資料搬移／rollback

- **migration**：無。
- **資料搬移**：無。
- **derived refresh**：無。
- **重匯**：無。
- **重產報表**：🔴 **需要**。字級與尺寸寫在產出的 HTML／SVG 裡，既有版本目錄
  **不會**因本案改變。要看到新版面必須重新產製報表。
- **rollback**：revert 後新產製的報表回到舊版面；既有產出不受影響。

## Activation

合併後對**新產製的**報表生效。既有版本目錄維持產製當時的版面。

## Open Questions

無。

⚠ 決策 8 表示本案是**當前最佳解，不是終局**。實作時不要為了「以後好改」預埋
設定層與抽象——真的要改時再改（見 design 的穩定性策略）。

## Acceptance Gate

動工前記錄現況版面量測值作為對照。逐項驗收，未執行與不適用分開揭露。

### 字級

| # | 判準 | 怎麼驗 |
|---|---|---|
| 1 | `h1` 28px、`h2` 24px、正文與表格 16px | 量測產出的 HTML |
| 2 | **圖內字實際顯示為 16px** | 🔴 量測**渲染後**的實際字級，不接受「SVG 裡寫了 16」 |
| 3 | 圖內字不再依賴顯示寬度反推 | 檢視實作：改變圖寬時字級不變 |
