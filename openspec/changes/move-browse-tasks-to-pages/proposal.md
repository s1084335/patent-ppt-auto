# Proposal: 瀏覽區作業頁面化

## Intent

把瀏覽專利區裡「要編一份名單」的作業搬到各自的獨立頁，瀏覽首頁只留帶待辦數的入口，
讓進頁面第一眼就看到專利表本身。

## Why

瀏覽專利頁目前把三塊維護作業塞進收合面板。2026-07-28 使用者說「太亂了」後曾重排一次
（把它們收進 `details`），但那只解決了「佔版面」，沒解決規模問題：

- **專利權人代碼與中文名**：實測前端有 **65 支相關函式，從行 1187 橫跨到 5937**。
  它有建組、AI 建議、待審覆核、未歸戶名單四段流程，是一個子系統，不是一個區塊。
- **TW 專利狀態管理**：要逐筆填一份「待登錄」名單。

收合面板容不下「一份要編的名單」——展開後把專利表推到畫面外，收合後又看不到還有多少
待辦。兩種狀態都不好用。

輪一（`add-prefilter-negative-keywords`）已把「獨立頁＋帶待辦數入口」這個模式用在新功能上
並驗收過；本 change 把同一模式套用到既有作業。

## What Changes

- **專利權人代碼與中文名**移至獨立頁；瀏覽首頁改為帶待辦數（未歸戶名稱筆數）的入口。
- **TW 專利狀態管理**移至獨立頁；瀏覽首頁改為帶待辦數（待登錄件數）的入口。
- **文獻備註留在瀏覽首頁**：它只有一顆按鈕與覆蓋率提示，沒有名單要編。
- 入口卡片抽為共用元件（輪一已建立其一，本 change 收斂為同一份）。
- 兩個新頁**均無左導覽項**，自瀏覽首頁入口進入。

**本 change 不新增任何功能。** 所有搬遷的功能行為與搬遷前完全相同。

## Scope

- 兩塊作業的掛載點變更與入口建立。
- 入口待辦數的取得（取自既有權威 API，不由前端自數）。
- 瀏覽首頁收斂。

## Non-goals

- 不改任何被搬遷功能的行為、資料契約或 API。
- 不搬文獻備註。
- 不新增左導覽項。
- 不動輪一建立的初階篩選頁。
- 不重構那 65 支公司名函式——**只改掛載點，不動函式本體**。

## Capabilities

### New Capabilities

無。

### Modified Capabilities

- `workspace-and-browse`：`WSP-012` 的 TW 狀態管理由「瀏覽介面的預設收合區塊」
  改為「獨立頁，瀏覽介面提供帶待辦數的入口」；其餘行為（只列待登錄、九項值域、
  單筆首次登錄、衝突處理）完全不變。

## Impact

| 面向 | 影響 |
|---|---|
| DB | 無 |
| 後端 API | 無變更；入口待辦數使用既有端點 |
| 前端 | 掛載點變更、兩個新頁、瀏覽首頁收斂 |
| 既有測試 | `test_api_frontend.py` 的相關靜態斷言需改為新掛載點 |

### Migration／資料搬移／rollback

- **migration**：無。
- **資料搬移**：無。
- **derived refresh**：無。
- **重匯**：無。
- **rollback**：純前端掛載點變更，revert commit 即還原。

## Activation

合併後即生效，不需設定。

## Confirmed Decisions

| # | 決策 | 來源 |
|---|---|---|
| 1 | 要編名單的區塊各自一頁，首頁只留入口 | 使用者 2026-08-21 |
| 2 | 兩個新頁**無左導覽項**，沿案件比對既有模式 | 使用者 2026-08-21 |
| 3 | 排在輪一之後——模式先在新程式碼驗證，再套用到既有子系統 | 規劃決定 |
| 4 | 文獻備註留在瀏覽首頁（沒有名單要編） | 規劃決定，使用者未反對 |

## Open Questions

無。

## Acceptance Gate

| # | 判準 | 怎麼驗 |
|---|---|---|
| 1 | **搬遷前後功能等價** | 每個搬走的功能，搬前跑一次、搬後跑一次，逐項對照輸出 |
| 2 | 入口待辦數取自權威 API | 測試斷言前端不自行計數；數字與後端端點回傳一致 |
| 3 | 兩頁均無左導覽項，但可自入口進入 | 前端斷言 |
| 4 | TW 狀態的既有行為未變 | `WSP-012` 其餘五個 scenario 全部重驗 |
| 5 | 公司名治理的既有行為未變 | `company-governance` 相關測試全綠 |
| 6 | 文獻備註仍在瀏覽首頁 | 前端斷言 |
| 7 | 既有測試不放寬 | 改斷言可以，降低要求不行；每處改動註明理由 |
| 8 | 範圍回歸 | 前端契約測試、公司治理、TW 狀態相關測試全綠 |

⚠ 判準 1 是本 change 的核心：這是純搬遷，**任何行為差異都是缺陷**，不是「順便改進」。
⚠ 若搬遷過程中發現非改函式本體不可，應停下重新評估耦合，不得硬拆（見 design 風險）。
