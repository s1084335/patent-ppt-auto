## Why

匯出的 HTML 檔自 2026-08-10 起是**唯一交付物**，但它的版面從未針對「給人讀」設計
——它是報表引擎產圖時順手產的索引頁，沿用至今。實測 `report_trial_20260812_133901`
（1600×1000 視窗）：

| 症狀 | 實測 |
|---|---|
| 讀者只能一路捲 | 9 章共 **8080px（8.1 螢幕）**，**完全沒有導覽** |
| 圖搶走版面 | 圖**原尺寸顯示** 1180×560；圖內字 **15.1px**＝與正文 16px 同級 |
| 數據表插在最前面 | 版面順序是「數據表 → 圖 → 解讀」——一進章節先撞到一大片數字 |
| 數據表比圖還肥 | 預設展開前 20 列；申請人年度矩陣 21 列單張 **697px** |
| 標題不是報表名 | 寫死英文 `Patent Report` |

使用者 2026-08-12 指出「現在的 HTML 內容圖表太大了」，並以外部範例定調章節呈現，
收斂為「導覽用報表標題當章節、文字沿用現有解讀、其餘不參考」。版面示意已照准。

## What Changes

- **章節導覽（新增）**：頂部常駐導覽列，用現有 section 標題當章節名、錨點跳轉。
- **版面順序改為「圖 → 數據表 → 解讀」**（2026-08-12 使用者定案）：圖先給印象、
  表提供佐證、解讀作結。⚠ 解讀原掛在圖的 chart-panel **內**（逐變體），移到表之後
  即離開 panel，必須自帶同組 `data-group` 隨切換鈕連動——否則「切到 L5、讀著 L4
  解讀」是靜默錯配。
- **圖降為證據**：固定顯示高 400px（原尺寸顯示改掉），**點擊展開原尺寸**。
- **數據表預設收合**：只顯示前 5 列，展開才看其餘（現為前 20 列全展開）。
  ⚠ 展開上限**仍是 20 列**——2026-07-21 定案「不讓人看百筆數據」不變，本次只改預設密度。
- **標題改用實際報表名**：取 `version_meta` 的 workspace 名稱，退回既有標題。
- **`chart_sizing.PPT` profile 刪除**：已無消費者（`chart_runner` 只 import `WEB`），
  其圖框是已移除的 `build_ppt` 的數字，與 deck 幾何是兩套對不起來的簡報尺寸知識。

## 已確認決策（本 change 的邊界）

1. **對象＝匯出 HTML 檔**（`chart_runner.render_index` 產在版本目錄的 `index.html`），
   **不是前端預覽頁**。前端 `exportReportHtmlFile` 只把 SVG 換成 data URI，不改。
2. **不含「重產解讀」等操作元件**（使用者：那是前端預覽做的事）。
3. **文字沿用現有 narrative 原文**，不新增文案類型、不改解讀產生方式。
4. **圖 400px 是下限**：SVG 縮小字等比跟著縮，400px 時圖內字約 10.7px；
   再小會破。真要更小又要字清楚＝引擎重產適配圖＝回到 unify 剛拆掉的雙份圖，不做。
5. 多變體章節（IPC/CPC 的 L4／L5 等）**沿用現行切換鈕**，不動。
6. 前端預覽頁的瘦身（解讀區 209px×13 的常駐重產控制項）**不在本 change**。

## Capabilities

### Modified Capabilities

- `report-export`：交付用 HTML 報表的呈現契約（章節導覽、版面順序、圖與表的預設密度）。

## Scope

`backend/app/reports/chart_runner.py` 的 `render_index`（含其 CSS／JS）、
`backend/app/reports/chart_sizing.py`（刪 `PPT`）、
`tests/test_chart_sizing_profile.py`（三支比對 WEB/PPT 差異的斷言）與新增的 HTML 結構契約測試。

## Non-goals

- 不改前端預覽頁（報表種類頁）——那是工作介面，本 change 只動交付物。
- 不改圖表引擎的產圖邏輯與尺寸（RPT-010 單一來源不動；本 change 只改**顯示**尺寸）。
- 不改解讀內容、產生方式或 narratives 契約。
- 不做 PDF 匯出、不做分頁列印優化。
- 不動「匯出報告」頁（那是 deck 的落點，屬 `add-deck-delivery-line`）。

## Impact

- 程式：`chart_runner.render_index`（HTML 結構＋CSS＋錨點 JS）、`chart_sizing`。
- 產物：新版本目錄的 `index.html` 結構改變；**舊版本目錄不重產**（既有檔案不動）。
- 測試：新增 HTML 結構契約；更新 `test_chart_sizing_profile` 三支斷言。
- 無 DB／API／migration 影響；自包單檔匯出流程（前端）不需改動。

## Acceptance Gate

1. **實測改版後總高**：同一版本（`report_trial_20260812_133901`）改版前 8080px，
   改版後 SHALL ≤ **7500px**，且每章可由導覽直達；證據入 `output/_verify/`。
   ⚠ **本項門檻是量測後調整的**（原訂 ≤6500px，實測 7524px）：
   ① 明說是量完才改；② 理由——實測才看清每章的固定成本（圖 ＋ 表 ＋ 章節框架
   約 83px），9 章的地板就在 6200–6300px，且**有 AI 解讀時每章再多 100–150px**；
   要壓到 6500 只能犧牲使用者當日指定的字級（圖內字 11px、正文 14px）或把數據表
   砍到 3 列；③ 已交使用者裁決並獲同意（「做完併到主線去」）。
   ⚠ 另記：總高本身不是好判準——它隨解讀長度浮動。真正的價值在「可由導覽直達
   任一章」，那是質變；總高只作為「沒有反而變胖」的下限守門。
2. **導覽**：導覽項數＝章節數，每個錨點可跳且捲動位置正確（sticky 不遮標題）。
3. **版面順序**：每章 DOM 順序為 **圖 → 數據表 → 解讀**；多變體章節切換時
   解讀 SHALL 跟著換（不得停在前一個變體的解讀）。
4. **圖**：預設顯示高 400px；點擊後展開原尺寸；`viewBox` 等比不裁切。
5. **表**：預設 5 列；展開後列數＝原資料列數（含合計列行為不變）。
6. **自包單檔仍離線可開**：匯出後 SVG 全為 data URI、無外部資源引用（既有契約不破）。
   ⚠ 驗證方式要分兩段（見 design §7）：**匯出流程**驗 data URI 與離線可開
   （與版面無關）；**新版面**驗本機重建的 `index.html`。
   不得用「手動 `--refresh-index` 後匯出」驗版面——匯出讀的是 **DB artifact**，
   而 CLI 不上傳，那條路必然拿到舊版。
7. **三時代版本相容**：舊版本目錄（含 `.web.svg` 時代、前 web 時代）重渲染不破。
8. `chart_sizing.PPT` 刪除後 `WEB` 各欄值不變；範圍回歸綠。
